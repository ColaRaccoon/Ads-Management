# 파일 업로드 자동화 조사

조사일: 2026-09-21 / 대상: 현재 Meta Ads Performance Hub 코드와 공개 공식 문서.

후속 조사: [Cafe24·Meta API 비용 및 자격](./cafe24-meta-api-cost-eligibility-2026-09-21.md). Cafe24 자사몰 5개 이하의 무심사 설치 경로와 Meta 권한 수준/운영 티어의 차이를 추가 확인했다. 아래 초기 조사에서 미확인으로 남긴 항목은 후속 문서의 확인 내용을 우선한다.

이 문서는 구현 전 타당성 조사다. 실제 판매자 계정의 권한, 계약, API 응답 또는 다운로드 파일과의 수치 대조는 수행하지 않았다. ‘공식 지원 확인’, ‘구현 제안’, ‘추가 확인 필요’를 구분한다. 공개 API 존재는 모든 계정의 사용 자격이나 화면 자동화 허가를 뜻하지 않는다.

## 결론

- 이 프로그램에 파일을 넣는 단계는 폴더 감지와 기존 가져오기 기능을 연결하면 거의 전부 자동화할 수 있다. 파일 취득까지 자동화되는 것은 아니다.
- Meta 광고와 Cafe24 주문은 공식 API를 통한 정기 수집을 우선 추진할 수 있다. 기존 CSV와 수치·식별자·집계 기준의 일치 검증이 전제다.
- 쿠팡은 주문·상품·정산 API와 공식 광고 보고서 예약 기능을 조합한다. 현재 판매 분석 파일, 1일 전환 광고 상세 파일, 프로모션 파일의 완전 대체는 아직 확정할 수 없다.
- 화면 클릭·스크롤·다운로드 자동화는 기술적으로 가능하지만, 해당 서비스의 허용 범위를 확인해야 한다. 공개 자료에서 허용을 찾지 못한 경우를 ‘금지 확정’이나 ‘허용’으로 바꾸어 해석하지 않는다.
- 원가·계약 물류비·평균 반품률 등 사내 기준값은 원천 시스템이 있어야 자동 수집할 수 있다. 상품 판매 API만으로 생성할 수 없는 정보다.

## 현재 코드에서 확인한 입력

| 입력 | 코드 위치 | 자동화 시 주의점 |
| --- | --- | --- |
| Meta 광고 일별 CSV | `apps/api/src/domain/meta-ad-daily-csv.ts` | 광고/광고세트/캠페인 식별자, USD 지출, 구매·장바구니·영상지표. 광고 게재 상태도 필수 컬럼이다. |
| Meta 광고세트 CSV | `apps/api/src/uploads/uploads.controller.ts` | 서버에는 별도 가져오기 경로가 있다. 일별 광고 수집과 중복 집계를 피해야 한다. |
| Cafe24 주문 CSV | `apps/api/src/domain/cafe24-csv.ts` | 주문번호와 품목별 주문번호를 구분. 총 주문금액·총 결제금액·상품 판매가의 의미를 유지해야 한다. |

| 쿠팡 광고 XLSX | `apps/api/src/domain/coupang-ads-xlsx.ts` | 집행 옵션과 전환 옵션을 구분하며 총/직접/간접 1일 전환 지표를 요구한다. |
| 쿠팡 프로모션 XLSX | `apps/api/src/domain/coupang-promotion-xlsx.ts` | 프로모션 가격, 시작·종료일, 상품·옵션 매칭이 핵심이다. |
| 원가/마진 CSV·텍스트 | `apps/api/src/domain/coupang-margin-csv.ts` | 원가, 물류비 등 내부 기준값을 포함하며 적용일 관리가 필요하다. |
| 가격 텍스트 | `apps/api/src/domain/coupang-price-text.ts` | 상품명과 판매가 입력. 현재가 수집과 과거 기본판매가 보존은 별개다. |

서버는 이미 파일 검증, 업로드 배치, 중복 검사, 충돌 정책, 실행자 기록을 갖고 있다. API 컨트롤러는 `imports.manage` 권한을 요구한다. 조사한 소스에서는 Meta/Cafe24/Coupang 외부 API 커넥터나 정기 수집기는 확인되지 않았다. 자동화 계정 인증과 작업 스케줄러를 추가해야 하며, 현재 브라우저 로그인 쿠키를 영구 인증수단으로 가정하면 안 된다.

## Meta

**공식 지원 확인:** Meta가 제공하는 Marketing API 컬렉션에는 광고 Insights 조회, 일별 분할, 지출·노출·클릭·액션·영상 지표가 제시되어 있다. 자사 광고 계정과 타사 광고 계정은 Standard/Advanced Access 요건이 다르다. [Meta 공식 Postman 문서](https://www.postman.com/meta/facebook-marketing-api/documentation/0zr4mes/facebook-marketing-api-mapi)

**구현 제안:** 읽기 목적의 `ads_read`를 중심으로 앱·광고계정 권한을 설정하고 광고 단위 일별 데이터를 정기 수집한다. 광고 상태와 예산처럼 성과 조회와 성격이 다른 값은 별도 광고/광고세트 조회가 필요할 수 있다. 타사 계정 연결 시 권한 심사와 사업자 확인 등 실제 앱 요구사항을 확인한다.

**현재 앱과의 차이:** CSV의 ‘결과’는 캠페인의 목적에 영향을 받으므로 구매 건수로 일괄 해석하지 않는다. 구매/장바구니 액션 종류, 기여기간, 전환 보고시점, 계정 시간대, 통화를 고정해 비교한다. 현재 코드는 USD 중심이므로 KRW 광고계정 응답을 그대로 `spendUsd`에 넣으면 안 된다. 영상 3초·구간별 지표와 `shop_clicks` 등은 선택한 API 버전에서 가용성을 개별 확인한다. 도달은 중복 제거 지표이므로 광고별 도달의 합과 광고세트 도달이 같다고 가정하지 않는다.

**화면 자동화 정책:** Meta 공식 설명은 허가 없는 자동 데이터 수집을 약관 위반으로 설명한다. 본인 계정이라는 사실만으로 Ads Manager 매크로가 허용된다고 판단할 수 없다. 공식 API가 우선이다. [Meta의 자동 수집 관련 설명](https://about.fb.com/news/2021/04/how-we-combat-scraping/)

**확인 한계:** 개발자 Insights/get-started 페이지는 이번 조회에서 429가 반환되었고 자동수집 약관 URL은 로그인으로 이동했다. 따라서 공식 Postman 자료와 Meta의 공개 설명을 근거로 했으며 최신 약관 전문을 모두 검증했다고 주장하지 않는다. [자동수집 약관 원문 위치](https://www.facebook.com/legal/automated_data_collection_terms)

## Cafe24

**공식 지원 확인:** Admin API에 주문, 주문 품목, 주문 쿠폰, 환불 조회가 있고 주문 읽기 권한은 `mall.read_order`다. 주문 변경 조회 등 일부 API는 특정 클라이언트 전용으로 표시되어 있어 일반 권한으로 사용할 수 있다고 가정하지 않는다. [Admin API](https://developers.cafe24.com/docs/ko/api/admin/)

**인증:** OAuth 앱 등록·쇼핑몰의 접근 동의를 거쳐야 한다. 공식 시작 가이드는 Access Token 2시간, Refresh Token 14일을 안내한다. 토큰 갱신과 갱신 결과 저장을 자동화하고 인증 철회나 장기 중단 시 재연결을 요청하는 구조가 필요하다. [인증 시작 가이드](https://developers.cafe24.com/docs-new/en/docs/guide/intro)

**허용 조건:** 개발자 약관의 Apps 부속조항은 앱 등록, 발급 키 사용, API 가이드·운영정책 준수를 요구한다. 개인정보 수집 최소화도 명시한다. 자사몰 설치와 외부 판매용 앱의 배포·심사 경로를 구분해서 확인한다. 이 약관은 관리자 화면 매크로의 포괄적인 허가 근거가 아니다. [개발자 약관](https://partners.cafe24.com/terms), [API 운영정책](https://developers.cafe24.com/app/front/app/develop/api/operation)

**구현 제안:** 주문 목록과 품목 데이터를 정규화해 현재 주문 입력 모델로 가져온다. 주문 단위 금액을 여러 품목에 중복 합산하지 않도록 검증하고, 할인·쿠폰·배송비·취소·부분환불을 기존 CSV 계산과 대조한다. 웹훅은 적용 이벤트와 사용 자격을 확인한 뒤 추가하고, 정기 재조회로 누락을 보완한다. API 문서별 호출 한도 표현이 다르므로 단일 고정 속도를 믿지 말고 적용 API의 한도와 응답 헤더, 429에 따라 조절한다.

**남은 확인:** 관리자 화면의 수집 자동화 허용은 이번 공개 문서 조사로 확정하지 못했다. API 경로로 해결하면 이 불확실성에 의존할 필요가 없다.

**후속 확인:** 공식 FAQ는 자사몰 5개 이하에 한하여 테스트설치로 별도 앱 심사 없이 이용 가능하다고 명시한다. 6개 이상은 정식 출시가 필요하며 테스트 한도 상향은 제공하지 않는다. [앱 서비스 FAQ](https://developers.cafe24.com/ko/app/front/common/concepts/appservicefaq)

## 쿠팡 판매·정산·가격

**공식 지원 확인:** Open API 목록에 상품, 판매자배송 주문, 반품, 정산, Rocket Growth API가 있다. WING에서 API 키를 발급하고 HMAC 인증과 연동 설정을 하는 공식 경로가 존재한다. 개별 계정 자격·IP 설정·키 만료는 연결 시 확인한다. [Open API 목록](https://developers.coupang.com/ko/api), [시작 안내](https://developers.coupang.com/ko)

**중요한 집계 차이:** 매출내역 조회는 매출인식일, 즉 구매확정 또는 배송완료 후 7일을 기준으로 조회한다. 현재 일별 판매 보고서와 같은 자료라고 볼 수 없다. 이 API는 정산 검증에 활용하고, 주문일 기준 매출은 주문·취소·반품 데이터로 별도 검증해야 한다. [매출내역 조회](https://developers.coupang.com/ko/api/settlement/sales-detail-query)

**로켓그로스:** 현재 공식 문서에 주문 API가 있다. ‘로켓그로스는 API가 없다’는 판단은 부정확하다. 다만 문서는 출고일 이후 주문을 지원하고 해당 목록 API는 분당 50회 제한이라고 명시한다. 미출고·즉시취소를 포함한 당일 판매 분석 파일을 완전히 재현한다고 보장할 수 없다. [로켓그로스 주문 API](https://developers.coupang.com/ko/api/rocket-growth/rg-order-apilist-query)

**가격:** 상품 API로 등록된 상품의 가격을 조회하는 방향을 검토할 수 있다. 고객에게 보이는 쿠폰 적용 최종가, 프로모션가, 내부 기본판매가는 구분해야 한다. 현재 가격을 과거 날짜에 소급 적용하지 않도록 변경 이력을 보존한다.

## 쿠팡 광고

**공식 지원 확인:** 상품 광고 보고서 예약 기능은 일/주/월 주기와 지정일 오전 8시 자동 생성을 안내한다. 따라서 보고서를 매일 직접 생성하는 작업은 공식 기능으로 줄일 수 있다. [보고서 종류·예약 기능](https://ads.coupang.com/analysis/02)

별도로 ‘자동 광고 보고서’ 기능도 공개 안내되어 있다. 2025-03-21 안내에서는 상품광고 대상이며 NCA·브랜드광고는 제외한다고 설명한다. 현재 계정에서의 제공 범위는 다시 확인해야 한다. [자동 광고 보고서 안내](https://ads.coupang.com/blog/72)

**미확인 사항:** 공개 Open API 목록에서 현재 XLSX와 같은 광고 상세 보고서 API는 확인하지 못했다. 이것은 제휴사 전용 API까지 존재하지 않는다는 뜻이 아니다. 예약 생성이 이메일 첨부 발송, 서버의 자동 파일 취득, 현재 1일 전환 상세 컬럼 지원까지 보장하지도 않는다.

**진행 경로:** 기존 상세 보고서의 공식 예약 설정 → 실제 생성 파일과 현재 파서 대조 → 공식 전달/다운로드 인터페이스 또는 승인된 파트너 API 확인 → 가능하면 자동 수신 후 가져오기. 자동 수신 경로가 없다면 사람이 다운로드하고 로컬 프로그램이 이후 처리를 맡는 방식이 현실적인 중간 단계다.

## 쿠팡 프로모션과 내부 원가

프로모션 API는 즉시할인·다운로드 쿠폰, 계약, 예산, 캐시백 중심이다. 현재 XLSX의 프로모션 가격·기간·노출영역·성과와 같은 데이터인지 확인되지 않았다. ‘프로모션 API’라는 이름만으로 기존 파일을 대체하지 않는다. [프로모션 API 목록](https://developers.coupang.com/ko/api/promotions)

원가 파일은 원가·물류비·반품률 등 내부 기준을 포함한다. ERP/회계 시스템/담당자가 관리하는 원본 파일 중 실제 원천을 확인한 뒤 읽기 연동 또는 파일 감지를 적용한다. 원가 변경의 적용일은 파일 다운로드일로 자동 지정하지 않는다. 하나로 배송비가 어느 업체의 어떤 시스템에서 오는지는 코드만으로 특정할 수 없으므로 별도 업체 API 지원을 추정하지 않는다.

## 매크로·스크롤·크롤링의 판정

| 방식 | 기술적 가능성 | 정책/운영 판정 |
| --- | --- | --- |
| 공식 API | 지원 데이터에 가능 | 발급 권한·사용 목적·호출 한도·운영정책 안에서 사용 |
| 서비스 자체 보고서 예약 | 쿠팡 상품광고에서 확인 | 공식 기능 범위에서 사용. 파일 취득 경로는 별도 확인 |
| 받은 파일의 로컬 감지·가져오기 | 모든 현재 입력에 구현 가능 | 외부 사이트에 자동 접속하지 않음. 다운로드 후 반복 작업을 줄이는 경로 |
| 화면 클릭·스크롤·다운로드 | 일반적으로 구현 가능 | Meta는 무허가 수집 제한 근거 존재. Cafe24/WING/쿠팡 광고센터는 본 업무에 대한 포괄 허용 미확인 |
| 화면 내부의 비공개 요청 재현 | 기술적으로 가능한 경우 있음 | 공식 API 지원 또는 허용의 근거로 인정하지 않음 |

쿠팡 광고 약관 제22조는 개별 광고계약·기본거래계약·별도 약관의 적용 관계를 규정한다. 공개 광고정책만으로 WING 자동화 권한을 확정할 수 없다. 광고 사이트 하단 ‘판매자 이용약관’ 링크 중 실제 내용이 쿠팡 라이브 약관인 문서도 확인했으며, 이를 WING 매크로 허용 근거로 사용하지 않았다. [광고 약관](https://ads.coupang.com/policy/)

허용된 화면 자동화를 구현할 경우 좌표와 고정 스크롤 횟수보다 버튼/화면 상태를 확인하는 방식을 사용한다. 로그인 만료·2단계 인증·CAPTCHA가 나타나면 중단하고 사람이 처리하도록 설계한다. 오류 시 반복 클릭하지 않고 해당 작업을 보류한다. 느리게 실행한다는 이유만으로 정책상 허용되는 것은 아니다.

## 권장 구현 순서

1. **다운로드 이후 자동화:** 전용 폴더에서 파일 저장 완료를 감지 → 헤더로 형식 구분 → 계정·기간 검증 → 기존 가져오기 처리 → 실패/미매칭만 표시. 일반 웹페이지가 PC 폴더를 영구 감시한다고 가정하지 않고 로컬 에이전트 또는 서버 접근 가능한 폴더를 사용한다.
2. **Meta와 Cafe24 API:** 연결 설정·비밀키 저장·정기 수집·토큰 갱신·재시도를 구현하고 동일 기간 CSV와 병행 비교한다. API 데이터도 기존 검증과 감사 기록을 거치게 한다.
3. **쿠팡 공식 API:** 판매자배송과 로켓그로스를 분리해 주문·반품·정산을 수집하고 현재 판매 보고서와 차이 사유를 분류한다. 기존 판매 파일 완전 대체 여부는 이 결과로 결정한다.
4. **쿠팡 광고·프로모션:** 예약 보고서 실제 제공 항목과 공식 수신 경로를 확인한다. 부족한 부분만 허용이 확인된 화면 자동화 또는 다운로드 후 자동 처리로 보완한다.

운영 설계 제안: 계정/판매처 식별자를 중복 키에 포함, 완료된 페이지·기간만 반영, 실행 중복 방지, 최근 기간 재수집으로 늦게 반영된 전환·취소 수정, 누락과 실제 0 구분, 수동 수정값 보존, 원본 출처와 실행 이력 저장, 문제 발생 시 마지막 정상 데이터 유지. 처음에는 매일 전일 데이터를 수집하고 재조회 기간은 각 지표의 지연·기여기간을 검증해 정한다.

## 완전 대체 판정에 필요한 검증

- 같은 계정·상품·날짜·통화·기여기간으로 기존 파일과 신규 수집 결과를 비교한다.
- 광고비/노출/클릭, 주문·수량·취소·실결제, 프로모션 적용기간을 각각 대조한다.
- 주말·프로모션 시작/종료·부분환불·여러 품목 주문·미출고·즉시취소 사례를 포함한다.
- 허용 오차는 지표별로 정하며 원인 없는 차이를 ‘API 오차’로 넘기지 않는다.
- API와 파일이 동시에 들어와도 이중 집계되지 않는지 확인한다.
- 여러 계정 연결 시 기존 외부 ID 키와 데이터 격리 구조를 별도 점검한다.

## 회사에 문의할 구체적인 내용 — 발송하지 않은 초안

**쿠팡 WING/Open API 지원:** 당사 판매자 계정의 판매 분석 XLSX와 동일한 주문일 기준 옵션별 매출·총취소·즉시취소를 조회하는 공식 API가 있는지, 판매자배송과 로켓그로스 각각의 범위, 출고 전 주문/취소 제공 여부, 프로모션 XLSX와 동일한 조회 경로, 호출 한도와 데이터 지연을 문의한다.

**쿠팡 광고 지원:** 집행 옵션×전환 옵션별 총/직접/간접 1일 전환 보고서의 공개/제휴 API 제공 여부, 신청 자격, 기존 상세 보고서 예약 가능 여부, 첨부파일 전송 또는 공식 다운로드 경로, 자동 수집 허용 범위를 문의한다.

**화면 자동화가 필요한 회사:** ‘당사 소유 계정, 당사 성과 데이터만, 하루 정해진 횟수, 공식 화면의 조회·내보내기만, 광고 설정 변경 없음, 추가 인증 시 사람 처리’라는 구체적인 조건을 명시해 허용 여부와 적용 약관 조항을 서면으로 요청한다. 회사의 답변이 API만 허용한다면 화면 매크로까지 확대 해석하지 않는다.

**Cafe24 개발자 지원:** 자사몰 전용 설치 경로와 심사 필요 여부, 필요한 주문/쿠폰/환불 권한, 제한된 변경조회 API 대신 사용할 권장 동기화 방법, 적용 API 버전의 호출 한도를 확인한다.

공개 문서만으로 남은 허용 여부를 단정할 수 없다. 현재 단계에서 확보한 확실한 자동화 범위는 ‘다운로드 이후 처리 + Meta/Cafe24 공식 API 기반 수집 + 쿠팡 공식 API의 제공 범위 + 상품광고 예약 생성’이며, 쿠팡 전체 파일 취득까지 무인화한다는 약속은 추가 확인 후에 가능하다.
