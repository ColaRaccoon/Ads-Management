## 한 날짜·한 계정 대조 도구

`scripts/unified-stage11-reconcile.ts`는 `UNIFIED_STAGE11_RECONCILE_DATABASE_URL`을 사용하되 expected-host/database/role과 실제 DB identity가 일치하고 비관리자·비소유자 역할인 경우에만 진행한다. 명시한 platform/scope/date의 원천 어댑터를 READ ONLY로 재생하고 현재 publication의 사실과 비교한다. 큐 제출·lease claim·발행 메서드를 호출하지 않는다. 외부 수집 API도 호출하지 않는다.

예시 실행 형식(실제 값과 secret은 환경에서 주입):


출력은 재생/발행 fact hash, 구성요소별 원천 control, 제품 선택의 known/complete 매출·비용·이익·미배분 잔액, coverage·누락 원가·안전한 issue 및 발행 버전이다. 원문 주문키·원문 상품/옵션·URL·자격증명은 출력하지 않는다. scope도 hash로 출력한다. source/config와 report는 별도 읽기 전용 snapshot이므로 원천/설정이 동시에 바뀌면 불일치를 재검토해야 한다. 같은 계산 경로의 재생 대조이며 기존 화면의 독립 업무 산식·운영 화면을 새로 비교한 증거를 대신하지 않는다.

`PASS`는 실행불능 issue가 없고 확인 가능한 source control 차이가 모두0이며 전체 원천 partition을 새로 준비한 compact facts와 발행 facts의 정확 hash가 같은 경우다. 등록되지 않은 기준 제품명·허용 밖 계정은 source를 읽기 전에 거부한다. 미발행/이전버전/원천갱신/금액 차이는 `REVIEW_REQUIRED`와 exit2로 남긴다. read 오류·대상/역할 불일치에는 원문 오류 대신 안전한 고정 코드와 exit1을 출력한다. 운영 기능 OFF 준비 중에도 읽기 검증 프로세스의 환경을 따로 지정해야 하며 서버의 환경 플래그를 바꾸지 않는다.

## 권한 SQL·migration wrapper 격리 리허설

`scripts/unified-stage11-reconcile-roles.sql`은 **주 담당만 실행할 운영 제안**이다. 고정 새 역할 `meta_ads_unified_report/worker`를 NOLOGIN·NOINHERIT·비관리자로 만들고, report는 제품/규칙 SELECT·INSERT·UPDATE/audit SELECT·INSERT/4집계 SELECT/제한 큐 INSERT만 받는다. report에는 원천/이름판정audit SELECT가 없다. worker는 불변 trigger 아래 집계 DML·정확44개 원천/설정 SELECT만 받는다. source_connections는5열만 허용한다.

meta_ads **테이블** 소유자는 meta_ads_app이므로 그 구간은 SET LOCAL ROLE meta_ads_app으로 처리한다. public 네이버17개 **테이블**은 원문운영metadata상 **patima_app** 소유이므로 GRANT구간만 SET LOCAL ROLE patima_app을 사용하고 RESET한다. 각스키마USAGE는postgres/pg_database_owner가권한을가진schemaowner구간에서먼저부여한다. 실제management읽기로 app의schemaUSAGE grant option없음을 확인해 순서를교정했다. 첫운영적용본에서meta_ads schemaGRANT가경고로빠진문제는전체정책SQL을다시적용하지않고 `unified-stage11-reconcile-roles-schema-fix.sql`의2role USAGE grant만따로검토·적용하도록주담당에게전달했다. 기존 source RLS가 켜진 테이블에 새 worker SELECT정책을 추가할 뿐 기존정책·RLS on/off·FORCE·PUBLIC을 바꾸지 않는다. 관측public17개는RLS/FORCE둘다false이고그대로보존한다. USING(true)는 현재 공유 workspace 범위이며 계정/스토어 허용목록은 서버에서 별도 검사한다. 기존 PUBLIC/상속으로 credential 열/테이블이나 앱세션 SELECT가 생기면 SQL을 실패시켜 전부 rollback한다. 로그인/비밀번호·서버secret은 주 담당만 설정한다.
