## 이름·판매단위·계산

주문 이름은 함께배송 옵션의 실제 상품명, 주문 직접 이름, signature 이름, 검증된 옵션 상품명, 같은 store의 products 이름, 이름이 모두 없는 경우 canonical 표시명 순서로 확보한다. 외부 상품/옵션 ID 연결표는 사용하지 않는다. 내부 참조는 필요한 **이름**을 읽는 수단이며 판정은02 resolver로 다시 한다. 외부키 변경·같은 이름의 서로 다른 주문·stale 참조와 새 이름·signature 이름 변경을 검증했다.

원문/옵션·별칭으로 판정 가능한 제품과 판매단위를 우선한다. 단순 제품명 때문에 단품 원가를 선택하지 않으며, 같은 제품으로 검증된 구체 source 판매단위 이름을 보충한다. 명시 단품/1+1 옵션은 보존된 참조보다 우선한다. 실제 플로우라이트1+1을 단품으로 읽었던11,000원 차이를 이 경계에서 해결했다. 구성수량은 임의 추론하지 않아 physicalQuantity는 null이며 세트 총원가는 주문수량만 곱한다.

읽을 수 있는 이름이 미분류라면 canonical 참조로 기존 제품을 강제 확정하지 않는다. 원천 판매단위의 표시명과 기존 등록비용은 읽을 수 있으면 **COST_UNIT_ONLY / NAVER_SOURCE_COST_UNIT_RESTORED_PRODUCT_UNCLASSIFIED** 근거로 보존하고 productName은 null이다. 일반 옵션 `1+1`만으로 무관한 미분류 제품이나 원가를 확정하지 않는다. 이는 네이버 기존 비용 숫자를 유지하는 것과 통합 제품 분류를 구분하는 계약이다.

원천 판매단위/그룹 이름·별칭을 날짜/스토어 범위 이름규칙으로 구성한다. source-only 이름은 별도 기준명으로 유지하고, 01에서 확인한 버닝웨이브→버닝웨이브바, 두줄보호대→두줄무릎보호대, 버닝슬라이드→버닝 슬라이드만 명시 연결했다. 부모가 확인된 기준제품인 경우 자식 이름의 공백 차이는 그 source 그룹 관계로 복원하며, 자식이 별도 기준제품으로 판정되면 자식 판정을 우선한다. 카프슬리브/쿨토시는 임의 병합하지 않는다. 이름규칙을 운영 DB에 저장한 것은 아니다.

SALE/paymentDate만 상품매출로 읽고 productPaymentAmount에서 취소/쿠폰을 다시 빼지 않는다. 비용은 최신 날짜 이하 snapshot과 활성 개별설정의 적용일·실제 시각을 비교한다. 최신 표의 단위 누락/우선 개별설정 만료 시 옛 비용을 살리지 않는다. 명시0과 null/잘못된 금액을 구분한다. API 수수료는4필드 존재마스크와 존재값 합을 보존하고 모두 없을 때만 유효 요율을 적용한다. 소수2자리 기존 Math.round 의미와 그룹/일 매출10% VAT를 Decimal로 보존한다. 부모와 자식을 동시에 더하지 않으며 그룹 VAT의 원단위 잔액을 한 번 배분한다.

광고는 DA의 활성·CONFIRMED·PASSED 업로드 연결 비용만 채택한다. 현행 원천은 정상 복수 업로드를 허용하므로 유효 파일 전부를 합산하며 복수 자체는 누락 오류가 아니다. 명시 replacement 계보가 있는데 이전 파일이 잘못 active로 남았으면 조상 비용을 제외하고 손상 진단을 남긴다. 계보 순환·금액 오류·실제 읽기 실패는 PARTIAL이다. 그룹 광고는 한 번 기록하고 이름/별칭으로 찾은 자식이 여러 제품이면 UNALLOCATED다. 전환매출은 참고값으로만 보존한다.

배송수입·배송비·가구매는 NAVER 소속의 store/day 공통 사실이며 제품에 반복 차감하지 않는다. 사용 가능한 저장 배송 구성요소를 우선하고 없으면 기존 SALE+source 매핑 주문의 packageNumber(없으면 orderId) 고유수×배송단가와 배송수입 합을 사용한다. 설정 null의 기본3,500과 설정 SELECT 실패를 구분한다. 저장 요약과 원천 주문이 모두 없으면 완료0원을 만들지 않는다.

## coverage·신선도

입력 존재/계산 가능성과 `ESTIMATED`를 구분한다. 저장 계산 버전·시각·지문 부재는 신뢰 진단이며 숫자를 모두 버리는 조건이 아니다. malformed 선택적 sync/저장 메타도 정상 금액을 지우지 않는다. 저장 버전과 원천보다 오래된 계산시각을 진단에 남긴다.
