## 선택·캐시·발행 일관성

5개 플랫폼 체크박스가 서버 조회의 포함 범위를 바꾸며 KPI·표·그래프·당기·전기에 같은 선택을 사용한다. Meta/Google에 Cafe24 매출을 붙이지 않고, 제외 비용을 남은 플랫폼에 재배분하지 않는다. 네이버는 읽을 수 있는 추정값을 유지하며 추정 표시와 물리적 누락을 구분한다. 부분 선택은 선택 플랫폼/범위 명칭을 사용한다. 차트 범례는 계열 표시만 바꾸며 합계·비중 분모·API 조건은 유지한다.

URL은 플랫폼·계정·제품·당기·전기·간격을 보존한다. 사용자 ID+권한과 정규화한 전체 API 조건으로 React Query 키를 구분한다. 이전 응답 placeholder를 사용하지 않고 새 선택 조회 중에는 로딩을 표시한다. 취소된 선택은 이후 페이지 요청·완료 응답을 폐기한다. 응답의 날짜·플랫폼·제품·명시적 계정 집합, `selectionHash`와 `snapshotHash`가 일치할 때만 패널을 함께 표시한다. 발행 변경 충돌은 전체 묶음을 한 번 다시 읽고, 계속 바뀌면 재조회 안내를 표시한다.

시계열은 100개 단위 cursor를 끝까지 읽어 최대 366일을 자르지 않는다. 진단 집계는 summary.coverage 전체를 사용하고, 상세 controlTotals는 초기 100행과 명시적인 **다음 진단 100개**로 조회한다. 페이지 변경도 같은 스냅샷만 이어 붙이고 충돌 시 모든 패널을 다시 읽는다. 이전 필터의 진단 페이지 결과·오류를 새 선택에 붙이지 않는다.

명시적으로 고른 계정·스토어는 플랫폼 off→on 뒤 복원한다. 제외 중 선택 기억은 URL의 `scopeMemory`에만 저장하고 실제 API `scopeKeys`에서 제외한다. Meta/Cafe24가 `LEGACY_UNBOUND` 키를 공유하는 경우에도 둘 중 하나가 선택됐으면 그 키를 유지한다. API의 범위 선택은 키 단위이므로 공유 키를 플랫폼별 독립 계정 선택으로 가장하지 않는다. 명시적 계정 선택의 첫 메타데이터 로딩 중에는 플랫폼 전환을 잠깐 비활성화해 선택 손실을 막는다. 기본 전체 계정 범위의 빠른 토글은 허용한다.

## 금액·단위·그래프 기준

금액·MER·툴팁은 원래 문자열을 정확히 표시한다. 금액에 Number를 적용하지 않는다. 금액은 원, MER·MER 차이는 배, 증감률·비중은 %, 비중 변화·전체 광고비 증감 기여는 %p다. 비율 표시는 BigInt half-up 소수 2자리이고, 서버의 원래 비율 문자열과 금액은 유지한다. 판매처 비중·증감 표시 연산도 BigInt를 사용한다. 전기 0은 신규 집행/해당 없음, 비양수 이익 기저는 증감액과 흑자·적자 전환을 우선한다. 기간 길이가 다르면 일평균을 함께 표시한다.

그래프 좌표에서만 Number를 사용하며 안전 범위 밖은 좌표를 생략하고 정확한 원금액 표를 유지한다. 완전 합계가 null인 날짜의 선을 끊고 완료된 0만 0으로 그린다. 네이버 ESTIMATED 자체는 선을 끊는 조건이 아니다. 고립된 완료일·하루 조회도 점으로 보인다. 날짜축·툴팁 syncId를 공유하고 부분 주·월은 실제 포함 날짜를 툴팁·표에 표시한다. 100% 구성은 완전하고 양수인 합계·음수 아닌 비중일 때만 그린다. 플랫폼을 토글해도 매체 색상은 유지된다. 7일 이동평균은 연속된 완료 일별 버킷 7개일 때만 표시한다.

실제 HTTP 합성 표본의 카드·비교표·툴팁 대조값은 다음과 같다. 운영 실적이 아니다.

| --- | ---: | ---: | ---: | ---: |
| 전체 | 6,000.777778 | 1,201 | 3,000.777778 | 1,724.877778 |
| 네이버 제외 | 4,000.123457 | 1,000.7 | 2,000.123457 | 999.423457 |
