## 이름·판매단위와 비용

외부 상품/옵션 ID와 기존 판매행의 상품 FK를 분류 조건으로 사용하지 않는다. 레거시 설정의 상품 FK는 표준명/표시명을 복원하는 JOIN에만 사용하고 이후 기준명·판매단위·유효일로 비용을 선택한다. 같은 이름/옵션의 상품 재등록은 자동 적용되고, 같은 ID의 이름 변경은 다시 판정한다.

기존 포함/제외 키워드와 유효일을 관측 상품명+옵션명에 적용해 EXACT 이름 근거를 생성한다. 기존 키워드 predicate에 한해 공백 제거 의미를 보존하며, 공통 이름 정규화는 NFC/공백 축약 정책 그대로다. 판매는 `product_name`+옵션, 광고는 실행 상품명만 평가한다. 우선순위 차이로 여러 후보를 숨기지 않고 `AMBIGUOUS`로 남긴다. 통합 NAME 규칙도 함께 평가한다.

01에서 확인한 버닝웨이브바1/2개입, 플로우라이트1/2개입, 한줄보호대2/4개입은 기준명으로 묶고 단위를 분리했다. 두줄보호대 정확 별칭도 보존한다. 동등성이 미확정인 다른 변형·혼합 세트는 별도 기준명을 유지한다. 단위 총원가는 판매 수량만 곱하며 실물 개수는 별도다. 물리 단위가 불명확하면 null을 유지한다. 비용 설정 계보별 최신 유효 이력을 먼저 고르고 같은 이름/단위의 복수 계보 충돌은 임의 최신 ID로 해결하지 않는다.

판매는 가상 주문으로 만들지 않고 `sale_line_key`, 원 판매방식·집계수량·주문건수 근거를 유지한다. 매출은 `NET_SALES_REPORTED`이며 `salesKrw`·선택된 net·취소액을 각각 근거 구성요소에 보존한다. SALES_IS_NET/NEGATIVE_ADD/POSITIVE_SUBTRACT로 이미 반영된 net에서 취소를 다시 빼지 않는다. 이번 실제 캡처는 sales 열과 net이 같고 취소 열은 음수 참고값이다. 음수 취소 정정245행의 매출·수량·비용 부호를 유지했다.

정상판매 계산:

```text
normalNet = reportedNet - manualSales
normalQuantity = reportedQuantity - manualQuantity
normalProfitBeforeAds = normalNet - productCost - globalSalesFee
  - fulfillmentShipping - expectedReturn - otherDirect - normalNet/11
```

전역 수수료율, 판매자배송비, 로켓그로스의 한아로/입고/출고비, 반품률×단가와 기타비를 별도 보존한다. 유효 비용일 양끝 포함·명시0원·누락null을 구별한다. 금액은 Decimal precision80으로 계산하고 제품/단위/일별 소수6자리 잔여를 결정적으로 배정한다. 해당 control의 `roundingAdjustment`에 저장 차이를 남긴다.

가구매는 기존 pipeline의 SELLER→GROWTH 집계 가용수량 순서와 매출 부족분 재배분을 보존한다. 저장 가구매 매출이 없으면 기존 baseSalePrice 스냅샷 fallback만 허용하며 현재 판촉가격으로 과거 스냅샷을 덮지 않는다. 가구매 원가/배송/수수료/VAT를 추가 차감하지 않는다. 별도 `MANUAL_PURCHASE_ADJUSTMENT` SaleFact에서 업체비 `manualVendorFee`만 한 번 차감하며 공통비에 중복 반환하지 않는다. 스냅샷 총액 불일치·중복·수량초과·이름/단위 모호성은 정상매출/완전이익을 보류한다. 모호한 제품 후보만 보류하고 무관한 제품은 보존한다. 미분류 가구매를 무관한 미분류 판매그룹에 연결하지 않는다.

광고는 `adExecutionProductName`에 귀속한다. 실행명이 공백/`-`인 경우에만 필드가 명시된 유효 ad/group/campaign 이름규칙으로 복원한다. 전환상품 ID/이름은 비용 귀속 조건이 아니며 전환매출은 `referenceConversionRevenue`에만 둔다. 여러 옵션·무매출·미분류·음수 정정 광고비를 모두 보존한다. KRW 환율은1이며 광고 전 판매이익과 광고비는 별도 출력이다.
