A/B 구현은 병렬로 진행했다. A/B는 서로의 구현을 검토했고 A는 공통 저장·선택·Decimal도 검토했다. 주요 지적/해결:

- 비활성 제품의 유효한 역사 규칙까지 사라짐 → 명시적 역사 NAME 규칙을 보존하고 충돌 회귀 추가.
- 표본의 판매단위/복원경로/요구 상태 타입 오류가 500으로 이어질 수 있음 → 입력 검증 및 400 처리.
- META SALE/CAFE24 AD_SPEND 참여 정책 → 플랫폼 구성요소와 대조해 거부.
- 선택된 NAVER 입력 항목이 아예 없는데 completeAmount가 생성됨 → expected applicable platforms 검사·회귀 추가.
- 제외 플랫폼 marker 없음 → 원천 읽기 없이 excludedByUser 메타데이터 제공.
- 판매단위가 복수일 때 이름 MATCHED만으로 비용이 확정될 수 있음 → unitPreview와 UNIT_REQUIRED, 명시 단위 조건 추가.
- 배분 payload가 참조하는 제품명을 변경하면 참조가 낡음 → 활성 배분 규칙을 종료/갱신하기 전 이름 변경을 거부.
- 독립 제품 포함어를 임의 결합한 모든 가능성을 저장 금지하면 정상 카탈로그도 금지됨 → 동일 predicate/구체적 충돌은 저장 거부, 실제 복수 제품 표본은 AMBIGUOUS 처리하는 계약을 명확히 함.
