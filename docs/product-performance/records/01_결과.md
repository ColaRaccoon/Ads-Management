## 2 결정한 계약과 이유

확정 내용은 [01_확정계약.md](01_확정계약.md)에 필드·산식 단위로 남겼다.

1. 고정 기준 제품명+이름/옵션 규칙으로 자동 분류한다. 외부 ID는 복원/추적/중복 방지에만 쓰며 상품 재등록에 수동 ID 연결을 요구하지 않는다. 동일명 주문 여러 건을 보존한다.
2. 제품과 판매단위를 분리한다. 실제 단품/세트 가격·원가를 보존하고 1+1 원가를 다시2배하지 않는다. 에어스텝퍼 동명 활성/비활성, 네이버 카프슬리브/쿨토시 충돌은 임의 병합하지 않는다.
3. 사용자 확인으로 쿠팡 기존 CSV는 하나의 업로드 범위다. 계정 입력/계정 UI를 새 선행 조건으로 만들지 않는다.
4. 사용자 추가 요청의5개 플랫폼 체크박스는 판매/광고/공통비 포함 범위를 바꾼다. Cafe24 판매를 Meta/Google에 각각 붙이지 않는다. 네이버 OFF면 해당 비용·잔액·품질 영향도 제외한다. 분석용 광고 필터는 선택 범위의 총액을 바꾸지 않는다.
5. 네이버는 기존 프로그램의 추정 정책을 허용한다. 정확도 입증·전수 재수집을 진행 조건으로 만들지 않는다. 존재하는 추정 수치와 실제 입력 없음/null은 구분한다.
6. Cafe24 등록매출과 주문 실결제는 분리한다. `[유튜브]` 완전 SALE 설정을 우선 적용하고 GOOGLE 광고 OFF와 무관하게 유지한다. Cafe24/네이버10%와 쿠팡1/11 VAT는 기존 업무 규칙으로 보존한다.
7. 광고 전 구성요소를 받아 광고를1회 차감한다. 쿠폰/취소/반품/배송/가구매의 포함 여부를 명시한다. 제품 배정합+미분류+미배분=원천액을 보존한다. 범위 이익에서는 미배분 광고·공통비도1회 반영한다.
8. Decimal 문자열 경계·저장 소수6자리·환율/규칙/계산 버전·기간비교·갱신/실패복구·권한/API 초안을 확정했다. 원천별 완결 버전을 독립 발행하며 네이버 오류가 다른 원천 조회를 막지 않는다.

미해결 사용자 업무 결정은 없다. 플랫폼 체크박스·API·화면의 실제 구현은 02~10의 담당 범위다.

## 3 실제 원천 조사와 한계

운영 프로젝트 `iygjmosbelbosfxidqxv`, DB postgres의 관리 읽기 연결을 사용했다. 연결 플러그인 list_projects는 Security Dev 프로젝트만 반환해 운영을 읽을 수 없었으므로 저장소의 기존 보호 자격증명 경로를 사용했다. 모든 조회는 `BEGIN READ ONLY`, statement_timeout8초, lock_timeout1초, `ROLLBACK`으로 감쌌다. 최초 identity에서 read_only=on을 확인했다. 개인정보/비밀/전체 payload는 조회 결과에 저장하지 않았다.
