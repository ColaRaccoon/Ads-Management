## 발견과 보완

운영 `production-reporting.Dockerfile`은 고정 C7 이미지의 API 산출물과 새 TypeScript 산출물을 `verify-source-setup-patch.mjs reporting`으로 대조한다. 기존 reporting 허용 목록에는 신규 `unified-performance` 모듈이 없어, 10까지 구현을 그대로 배포하면 `Unreviewed C7 API change`로 실패한다.

현재 `apps/api/dist/unified-performance`의 **66개 JS 파일**을 소스 역할별로 검토하고 reporting profile에 각각의 정확한 경로를 추가했다. 기존 tsconfig가 `.test.ts`를 제외하지 않아 배출하는 테스트 JS도 Google의 기존 방식과 동일하게 명시했다. 신규 어댑터/컨트롤러/도우미를 패턴으로 허용하지 않는다. 테스트 파일은 앱 모듈의 import 경로에 없고 배포 시 테스트 runner를 실행하지 않는다. 원래 source-setup profile에는 통합 모듈을 허용하지 않았다.

검토 범위는 계약/십진수/제품명·판매단위/플랫폼·배분·관계 계산, 기존 저장 원천 reader와 어댑터, management/report controller·service·repository·DTO, 큐/불변 발행·별도 worker, Nest 모듈 등록이다. `assertUnifiedEnabled()` 기본 OFF와 `data.read`/`products.manage`/`mappings.manage`/`operations.run`, 조회의 저장 집계 전용 경계를 확인했다. 역할·운영 데이터의 적합성은 A/B와 주 담당 검증 범위이며 이 빌드 목록 확인이 대신하지 않는다.

기존 Meta·Cafe24·쿠팡·margin 계산기 해시와 원래 모듈 삭제 감지는 유지했다. 기존 mappings controller에 대한 임의 변경도 여전히 실패한다. `app.module.js`는 기존 reporting 목록에 이미 포함되어 있으며 통합 모듈의 추가 import·등록을 확인했다.

## 운영 릴리스 차이 경고

운영 소스 `e80f7d1f3f6c574caebe16a962c74aca4cf24dfb`와 10 완료 HEAD를 비교하자 통합 기능 밖의 기존 구현이 되돌아간 것을 발견했다.

- `mappings/dto/mappings-transport.dto.ts`, `mappings/mappings.controller.ts`, `mappings/mappings.service.ts`: 운영의 제품 규칙 PATCH/apply endpoint와 날짜/regex 검증·재매핑·audit 경로가 빠져 있다.

주 담당에게 즉시 전달했다. **이 파일을 허용 목록에 추가해 퇴행을 통과시키지 않았다.** 주 담당이 기존 운영 구현을 보존하고 관련 회귀·전체 빌드를 다시 검증해야 한다. 이 기록은 발견 당시 차이를 보존하며 이후 통합 여부는 `11_결과.md`를 따른다.
