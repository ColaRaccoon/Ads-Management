2026-11-02. 사용자의 타입 오류 수정 및 운영 배포 요청에 따른 검증 기록.

**완료:** Google 타입 오류 4개 해소, 데일리 전체 제품 인쇄·엑셀 기능 운영 배포 성공. 운영 고정 커밋은 `a17038bb50eabd9c9804358b9890e51e4fe07e34`다. 이후 이 기록만 추가하는 커밋은 재배포하지 않는다.

## 원인 및 수정

원본 `38d9929`의 `ad-reader.ts`와 `native-google-ad.test.ts`는 Google 키워드 API를 호출하지만, 실제 matcher는 이전 버전이었다. `googleKeywordFromMapping`, `googleKeywordIdentity` export 두 개와 matcher/반환 함수의 추가 인수 정의가 없어 4개 TypeScript 오류가 발생했다.

운영 Railway 앱은 이미 `3a8e75b0350c385f0390f0029bc4898849cd9d02`로 실행 중이며, 누락된 Google 변경 `b1f54ae`와 Cafe24 옵션 확인 유지 수정 `e0148d8`이 이 커밋에 포함된다. 원본의 누락을 각각 `29fd74a`, `f862265`로 복구했다. matcher만 복사하거나 인수를 삭제하면 Google 개별 보고와 통합 보고의 제품 귀속이 달라질 수 있으므로 기존 운영 커밋 전체를 복원했다.

Google 모듈·daily-sync·통합 adapters/domain·aggregation/reconciliation·기존 domain/sales/coupang/metrics·Prisma를 운영 SHA와 비교해 diff 0을 확인했다. 계산식, 환율, 금액 반올림, 저장 결과, 제품 귀속 규칙을 운영과 동일하게 보존한다. 독립 읽기 전용 검토도 같은 결론이다. DB migration·원천 수집·발행 재실행·worker 재배포는 이번 범위에 없다.

배포 보호 검사는 신규 `daily-products.js`, `daily-products.test.js`, `daily-products-naver.test.js` 3개만 명시적으로 추가했다. 기존 보호 대상과 알 수 없는 모듈의 거부 동작은 유지한다.

운영 로그인 브라우저는 computer-use 창 연결 시 소유자 확인 오류로 연결하지 못했다. 따라서 운영 화면에서 금액을 재확인했다는 주장은 하지 않는다. 금액 보존 근거는 운영 계산 소스 동일성, 회귀 대조, 저장 결과를 재발행하지 않는 배포 범위다.

## 첫 배포의 산출물 검사 실패와 보완

`e328bdc`의 deployment `a6ae8c22-d01d-4b84-ae42-8e3a76bef7ad`는 API·웹 빌드와 C7 계산 모듈 보호 검사를 통과했으나 마지막 runtime closure 검사에서 실패했다. 새 Worker가 Turbopack의 실행용 JS 외에 `static/media/daily-products-xlsx.worker.*.ts`와 빈 `.js.map`을 생성했다. 기존 runtime guard는 앱 TS와 map 배포를 금지한다.

검사 예외는 추가하지 않았다. production Dockerfile의 기존 소스맵 제거 대상을 static까지 확장하고 해당 Worker의 중복 원본 자산만 제거한다. 같은 파일들을 제거한 실제 로컬 production 산출물로 브라우저 검사 6개와 Worker XLSX 다운로드를 다시 통과했고, 실제 static 자산을 기존 runtime guard로 검사했다. runtime guard 자체의 회귀 8개도 통과했다. 첫 실패 후 `RELEASE_GIT_SHA`는 이전 정상 SHA로 복구하고 다음 검증 후보를 준비했다. 기존 앱·worker는 재계산하지 않았다.
