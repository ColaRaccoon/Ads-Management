# 04 쿠팡 원천 통합

> 02단계 이후 필수 적용: [플랫폼 선택과 네이버 데이터 정책](플랫폼선택과네이버데이터정책.md). 이 추가 정책은 플랫폼 포함/제외·네이버 정확도에 한해 기존 전체 설계·공통 규칙·01 계약의 상충 문구보다 우선한다. 진행 중인 01 문서와 기록은 변경하지 않는다.

쿠팡 매출·광고비·직접비·가구매·배송·공통비를 쿠팡 소속으로 보존한다. 쿠팡을 제외하면 이 구성요소가 함께 빠지도록 계약을 제공하고, 제외 비용을 남은 플랫폼에 재배분하지 않는다.

이 세션은 쿠팡의 판매·광고비·정상판매 조정·가구매·배송비를 통합 계약으로 변환한다. 기존 쿠팡 손익 산식을 보존하면서 제품명으로 분류된 판매 사실과 광고비 사실을 분리해 반환한다.

## 시작 전 읽기

- [시작 안내](00_시작안내.md), [공통 작업규칙](공통_작업규칙.md).
- [마스터 계획서](../../제품별_통합성과측정_코드수정계획서_20261027.md)의 제품명/판매단위, 쿠팡 비용, 중복 제거, 계산/갱신 기준.
- [01 확정 계약](records/01_확정계약.md), [02 결과](records/02_결과.md).
- 03이 완료되었다면 [03 결과](records/03_결과.md)의 공통 계약 변경 사항도 확인한다.
- 현재 작업 트리와 적용되는 AGENTS.md. 다른 작업의 변경을 보존한다.

선행 조건은 02 DONE이다. 사용자 세션 순서는 03 → 04 → 05지만 자사몰/네이버 어댑터 구현을 쿠팡 코드의 의존성으로 만들지 않는다. 01·02가 정한 공통 계약을 사용한다.

## 목표와 이번 범위

1. 유효한 현재 쿠팡 판매·광고 원천을 선택하고 이름/옵션 규칙으로 기준 제품명과 판매단위를 판정한다.
2. 정상판매 매출·원가·수수료·배송·반품·기타비용·VAT와 가구매 조정을 구성요소로 보존한다.
3. 광고비를 비용 귀속 상품 기준으로 분류하고 전환상품/전환매출과 분리한다.
4. 소급 규칙과 미입력 비용의 상태를 전달하고 금액 보존 대조 자료를 만든다.

수정 대상 제안은 `apps/api/src/unified-performance/adapters/coupang.adapter.ts`, 필요한 쿠팡 전용 변환 함수와 검증 파일이다. 원천 DB 변경, 업로드/수집기 개편, 운영 권한 변경, 쿠팡 기존 화면 개편은 이번 범위가 아니다. 격리 환경에서 구현·검증하며 계정 정보가 부족하면 추정해서 채우지 않는다.

## 참고 코드

- `apps/api/src/coupang/coupang.service.ts`: 현재 판매/광고 선택, 상품·기간별 설정과 기존 보고서 조합.
- `apps/api/src/domain/coupang-profit-pipeline.ts`: reported sales, manual purchase, actual sales와 비용 계산의 경계.
- `apps/api/src/domain/coupang-profit-calculator.ts`: 판매 방식별 배송·반품·수수료·VAT 및 광고비 차감.
- `apps/api/src/domain/coupang-product-matcher.ts`: 포함/제외 키워드와 적용기간, 모호한 판정 처리.
- `apps/api/src/domain/coupang-price-resolver.ts`, `apps/api/prisma/schema.prisma`: 판촉/기준가격, 원가 이력, 판매행·광고행·가구매 모델.

## 구현 규칙

- 기준 제품명은 기존 표준 상품명과 원천 상품명/옵션명에서 판정한다. 외부 상품번호·옵션번호는 원천 추적용이며 제품 분류 조건이 아니다.
- 기존 자료에 판매계정 컬럼이 없다는 제한을 반영한다. 01에서 확정한 기존 데이터 범위를 사용하고 여러 계정이 섞인 자료는 명시적인 식별 근거가 생길 때까지 진단 상태를 유지한다.
- 판매는 유효한 현재 `sale_line_key`별 사실을 사용한다. 취소 차감 전 매출과 `net_sales_krw`의 의미를 구분해 취소를 두 번 차감하지 않는다.
- 쿠팡의 일별 판매 집계를 주문행인 것처럼 취급하지 않는다. 원천 집계 키와 포함된 판매 방식·수량을 유지한다.
- 비용 귀속 원천은 광고 실행 상품명/옵션명과 관련 참조다. `conversion_product_id`나 전환 상품명으로 광고비를 옮기지 않는다. 전환매출은 판매처 매출 합계에 추가하지 않는다.
- 정상판매에서 가구매 수량·매출을 제외하는 조정과 별도 업체 비용을 구분한다. 기존 pipeline의 조정 전/후 기준을 따라 가구매 원가·배송·수수료를 중복 차감하지 않는다.
- 판매자배송·로켓그로스 등 판매 방식별 물류비와 비용 이력을 보존한다. 모든 판매에 하나의 배송비를 일괄 적용하지 않는다.
- 단품·세트·용량이 달라지면 판매단위별 비용을 선택한다. 같은 이름/단위의 상품 재등록은 기존 이름 규칙을 자동 적용한다.
- 광고비 차감 전 판매 구성요소와 광고비를 별도 반환한다. 기존 최종 순이익에 다른 광고비를 무조건 추가 차감하는 방식은 사용하지 않는다.
- 원가와 가구매 스냅샷 등 필수 비용이 불완전하면 0원을 대입하지 않는다. 수집 완료 0원, 적용 없음, 누락, 계산 불가를 공통 상태에 맞춰 구분한다.

## 필수 병렬 분담

주 담당자는 최소 2명의 서브에이전트를 사용하고 공유 계산 함수의 수정 소유권을 먼저 정한다.

| 담당 | 독립 소유 범위 | 제출 내용 |
| --- | --- | --- |
| 서브에이전트 A | 쿠팡 판매·비용 변환 함수와 해당 검증 | 정상판매/가구매/판매 방식/원가 이력 대조 |
| 서브에이전트 B | 쿠팡 광고비 변환 함수와 해당 검증 | 비용상품/전환상품, 이름 규칙, 미분류 비용 대조 |
| 주 담당자 | 어댑터 조합, 기존 pipeline 추출/변경, 공통 계약, 회귀 검증 | 구성요소 연결과 전체 금액 보존 |

두 에이전트가 `coupang.service.ts` 또는 공통 calculator를 동시에 수정하지 않는다. 기존 계산 변경 필요 사항은 주 담당자가 모아 적용하고, 다른 담당자가 결과를 독립적으로 검토한다.

## 완료 검증

1. 01 기준 제품과 확보된 하루·7일·30일 원천을 기존 쿠팡 보고서와 대조한다. 매출·취소·광고비·비용·가구매 각각의 차이를 설명한다.
2. 상품/옵션 ID만 변경한 사례에서 이름 분류와 판매단위 비용이 그대로 적용된다. 이름이 다른 제품으로 바뀌면 과거 ID 판정을 재사용하지 않는다.
3. 직접/간접 전환 상품이 다른 광고, 같은 제품 여러 옵션, 무매출 광고비, 미분류 광고비를 포함해 비용 합이 보존된다.
4. 정상판매와 가구매의 수량·매출·비용 조정, 판촉가격, 비용 적용일 경계를 검증한다. 판매 방식별 배송비를 각각 대조한다.
5. 원천 재업로드/현재 버전 교체/취소 정정/판매 0건에서 중복과 이전 금액 잔존을 검증한다.
6. 알려진 판매·비용과 미분류/미확정 금액이 원천과 연결되며 누락을 완료로 표시하지 않는다.
7. 변경에 필요한 타입·계산·격리 DB 검증과 기존 쿠팡 회귀 검증을 실행하고 실제 결과를 기록한다.
