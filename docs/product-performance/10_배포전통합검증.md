# 10 배포 전 통합 검증

## 목표와 선행 조건

기능들이 함께 동작하고 기존 업무·권한·금액·성능을 보존하는지 검증한다. 09 DONE과 01~09 결과가 필요하다. 아직 운영 전환 단계는 아니다.

[시작 안내](00_시작안내.md), [공통 규칙](공통_작업규칙.md), 전체 설계의 11절, 확정 계약과 API 계약, 각 단계 결과의 잔여 사항을 읽는다.

## 이번 단계 작업

- 계획서 요구사항 → 코드 → 검증 결과의 대응표를 만들고 빈 기능을 확인한다. 발견된 결함은 이번 단계에서 수정·재검증한다.
- 여러 제품/판매단위/계정의 하루·7일·30일과 장기 집계로 광고비·매출·직접비·미배분 공통비를 대조한다.
- 외부 ID 변경 자동 분류, 이름 충돌, 소급 원가/규칙, 업로드 교체, 취소/반품, 중복 수집을 통합 검증한다.
- 실제 런타임 역할로 허용/거부를 확인한다. 관리 연결 성공을 앱 권한 증거로 쓰지 않는다.
- 병렬 재집계·중단·실패·복구·삭제/0건 정정·오래된 결과 표시를 검증한다.
- 기존 Meta·Google·쿠팡·Cafe24 화면의 기준선과 결과를 대조한다. 네이버 원천 쓰기 변화가 없는지도 확인한다.
- 조회/집계 실행계획과 p95, 메모리, DB 연결·동시성·타임아웃을 측정한다. 초기 p95 2초 목표와 실측 차이를 기록하고 병목을 해결한다.
- 현재 명령을 확인해 스키마 검증·타입 검사·빌드와 필요한 통합 검증을 실행한다.
- 신규 migration/역할/환경 설정/플래그/백필 범위/기존 수집 일정/복구 경로를 고정한 배포 자료를 만든다. 신규 테이블 추가가 공유 DB와 기존 앱에 주는 영향을 검토한다.

## 필수 병렬 분담

서브에이전트 A는 계산·DB 회귀, B는 권한·실패 복구, 여유가 있으면 C는 UI·성능을 담당한다. 주 에이전트가 결함 수정을 조정하며 같은 파일 동시 수정을 막는다. 각 검토자는 자신이 구현한 영역 외의 주요 결과를 교차 검토한다.

## 완료 조건

중대한 미해결 결함 없이 요구 검증을 통과하고 배포/복구 절차를 격리 환경에서 실행해 확인해야 한다. 실데이터가 없어 미확인인 항목은 명시하고 운영 전환의 차단 여부를 결정한다. 타입/빌드 통과만으로 완료하지 않는다.

`records/10_결과.md`, `records/10_배포복구계획.md`를 작성한다. 정확한 릴리스/마이그레이션 목록, 실행 순서, 관측·중단·복귀 조건, 롤백 후 데이터 보존 방식을 다음 세션이 바로 사용할 수 있게 남긴다. 다음 세션 11만 운영 변경을 담당한다.
