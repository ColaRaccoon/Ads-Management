# 02단계 이후 플랫폼 선택과 네이버 데이터 정책

2026년 10월 27일 사용자 추가 요구를 반영한다. **02~12단계는 이 문서를 필수로 읽고 적용한다.** 진행 중인 01 계획서·결과·진행표는 수정하지 않는다. 01의 완료된 계약을 입력으로 받되 02에서 이 변경을 후속 계약에 반영하고 차이를 기록한다. 01을 재실행하거나 네이버의 원천 정확도 입증 때문에 되돌리지 않는다.

이 문서는 플랫폼 선택과 네이버 정확도 처리에 한해 기존 전체 설계·공통 작업규칙·01 계약의 상충 문구보다 우선한다. 특히 ‘필터를 꺼도 총이익 불변’은 차트 범례 숨김에만 적용한다. **플랫폼 체크박스는 데이터 포함 범위를 바꾸므로 합계와 이익도 바뀐다.**

## 1 사용자 선택으로 포함하거나 제외

제품 성과 화면 상단에 플랫폼 체크박스를 두고 기본값은 전체 선택으로 한다. 네이버를 자동으로 빼거나 강제로 포함하지 않는다. 사용자가 포함 여부를 결정한다.

| 체크박스 | 포함되는 데이터 | 제외할 때 |
| --- | --- | --- |
| Meta 광고 | Meta 광고비와 해당 광고 지표 | 해당 비용·지표 제외 |
| Google 광고 | Google 광고비와 해당 광고 지표 | 해당 비용·지표 제외 |
| 네이버 | 네이버 DA 광고비, 스마트스토어 상품매출·직접비·배송/가구매 등 공통 항목 | 네이버 소속 항목 전부 제외 |
| 쿠팡 | 쿠팡 광고비, 상품매출·직접비·가구매/배송 등 비용 | 쿠팡 소속 항목 전부 제외 |
| 자사몰 Cafe24 | 자사몰 상품매출과 해당 원가·쿠폰·배송 등 판매 비용 | 자사몰 판매 항목 제외 |

광고 매체와 판매처가 다른 점을 사용자에게 짧게 설명한다. Meta와 Google은 같은 자사몰 판매 데이터를 볼 수 있으므로, 각각의 체크박스에 자사몰 매출을 붙여 중복 합산하지 않는다. Cafe24 판매는 독립된 체크박스에서 한 번만 포함한다. 네이버 광고 범위는 현재 수집 중인 DA이며 네이버의 모든 광고상품을 수집한다는 의미가 아니다.

체크 상태 변경은 조회/분석 조건만 바꾼다. 원천 데이터를 삭제하거나 수집·예약·연결 활성상태, 상품명 규칙, 비용 설정을 변경하지 않는다. 모든 조회 권한 사용자가 선택할 수 있으며 관리자 설정 변경 권한을 요구하지 않는다.

## 2 모든 결과가 같은 선택 범위를 사용

- KPI, 표, 그래프, 툴팁, 판매처 구성, 광고비 비중, 기간 비교, 관계 분석 및 해당 결과의 내보내기 기능이 있다면 내보내기까지 같은 선택을 적용한다.
- 부분 선택의 명칭은 ‘선택 플랫폼 매출’, ‘선택 광고비’, ‘선택 범위 추정이익’, ‘선택 범위 MER’로 한다. 화면 상단에 포함/제외 플랫폼을 명시하고 전체 제품 순이익으로 오해하지 않게 한다.
- 선택 범위 이익은 선택된 판매/비용과 광고비로 다시 계산한다. 예를 들어 Meta를 빼면 Meta 비용 차감도 빠져 이익이 높아질 수 있다. 이것이 실제 Meta 광고를 중단했을 때의 매출/이익 예측이라는 뜻은 아니다.
- 네이버를 빼면 네이버 매출뿐 아니라 원가·광고·공통비·미배분 잔액도 빠진다. 제외 비용을 남은 플랫폼이나 제품에 재배분하지 않는다. 기존 원천별 배분 사실을 유지하고 그 위에서 선택한다.
- 현재기간과 비교기간에는 동일 선택을 사용한다. 광고비 비중과 전체 대비 증감 기여의 분모는 **선택된 광고 매체 합계**다. 선택 변경 때 기간 합계부터 비율을 다시 계산한다.
- 차트 범례 클릭은 표시 계열만 숨긴다. 플랫폼 체크박스는 합계까지 바꾸는 별도 기능이다. 둘의 라벨과 동작을 구별한다.
- 전체 해제는 ‘플랫폼을 선택하세요’ 상태이며 KPI를 0원으로 만들지 않는다. 광고만 선택한 경우에는 광고비만 표시하고 매출·이익·MER는 해당 없음으로 한다. 판매만 선택한 경우에는 광고 전 이익을 표시하고 광고 후 전체 순이익이라고 쓰지 않는다.
- 선택 변경 뒤 이전 결과가 잠깐 새 선택의 결과인 것처럼 나타나지 않도록 로딩·응답 범위를 확인한다. 선택한 광고 매체를 해제하면 관계 분석 대상도 해제/재선택 안내하고 숨은 원천을 계속 사용하지 않는다.

## 3 서버와 저장 계약

조회 요청에 `platforms` 배열을 추가한다. 허용값은 `META`, `GOOGLE`, `NAVER`, `COUPANG`, `CAFE24`다. 미지정은 기본 전체, 명시적 빈 배열은 전체 해제로 구분한다. 중복·순서는 정규화하고 알 수 없는 값은 검증 오류로 처리한다.

응답에 `selectedPlatforms`, `excludedPlatforms`, `scopeLabel`, `metricAvailability`와 원천별 품질/기준시각을 반환한다. 선택한 원천 종류에 판매/광고가 포함되는지 판단해 ‘해당 없음’을 0과 구분한다. 판매/광고 원천을 선택했고 수집이 완료된 날의 실적이 0원이면 유효한 0원으로 유지한다. 역할별 허용 계정·스토어 검사는 기존대로 수행한다.

원천 및 일별 집계에 플랫폼 소속과 판매/광고/직접비/공통비 구분을 보존한다. API·React Query·서버 캐시·관계 분석 캐시에 정규화한 선택 목록을 포함하고, UI의 URL/저장된 조회 조건에도 같은 선택을 보존한다. 선택은 사용자 조회 상태이며 전역 수집 설정이 아니다.

제외한 플랫폼의 누락·원가 공백·정확도 경고는 선택 결과를 불완전하게 만들지 않는다. 해당 플랫폼은 `EXCLUDED_BY_USER`로 분리하고 `NOT_COLLECTED`와 혼동하지 않는다. 선택된 원천의 수집/계산 불가만 선택 범위 coverage에 반영한다. 제외 원천을 상세 조회하거나 추가 수집할 필요도 없다.

한 플랫폼의 수집/계산 실패가 나머지 플랫폼의 정상 집계 발행을 막지 않도록 원천별 결과를 보존한다. 원천/계정/날짜의 완결된 버전만 발행하고, 보고서는 선택한 버전 묶음을 일관되게 읽으며 `asOfBySource`를 반환한다. 중간 단계 일부 금액을 정상 버전으로 노출하지 않는다. 네이버를 제외한 조회가 네이버 장애·읽기 권한 부족 때문에 실패해서는 안 된다.

## 4 네이버는 기존 프로그램의 추정값을 허용

사용자는 네이버 프로그램 특성상 데이터 정확도에 한계가 있음을 수용했다. 네이버의 실제 정산액/실매출 정답과의 일치, 과거 반품의 전수 최신화, 타 플랫폼과 같은 수준의 수집 정확도는 **05·10·11 완료의 필수 조건이 아니다.** 정확도를 높이기 위한 네이버 프로그램 개편이나 원천 전수 재수집을 이 기능에 추가하지 않는다.

네이버에는 ‘추정 데이터’ 표시와 마지막 갱신/알려진 한계 설명을 제공한다. 기존 계산 버전의 한계나 지문 부재만으로 사용 가능한 숫자를 모두 숨기거나 전체 기능을 막지 않는다. 읽을 수 있는 저장 결과 또는 기존 계산 규칙으로 산출 가능한 값을 사용하고 계산 근거와 시각을 남긴다. 원천 정확도를 증명하려고 전량 재계산을 강제하지 않는다.

검증 초점은 **선택한 네이버 입력을 통합 프로그램이 의도대로 옮겨 계산하는지**다. 부모/자식 중복 합산, 광고비 이중 차감, 단위/환산 오류, 잘못된 상품명 분류, 제외 플랫폼의 잔존 금액은 그대로 검증한다. 기존 입력/업무 산식의 추정 오차와 새 구현의 버그를 구분한다.

물리적으로 읽을 수 없는 데이터, 이름을 판별할 수 없는 행, 필수 원가/환율이 없는 금액은 임의 숫자나 0으로 채우지 않는다. 수치의 존재/계산 가능 상태와 원천의 `ESTIMATED` 신뢰 표시를 분리한다. 모든 선택된 필수 항목이 수치적으로 계산되면 네이버 추정값을 포함한 합계를 추정 표시와 함께 제공한다. 입력이 없으면 확인된 부분 금액을 보여주고 사용자가 네이버를 제외할 수 있게 한다. `ESTIMATED` 자체를 오류나 누락으로 전파하지 않는다.

## 5 단계별 반영과 검증

02는 조회 범위·품질·관리 계약에 이 정책을 반영하고 `records/02_결과.md`에 01과 달라진 부분을 남긴다. 03~05는 원천 소속을 보존한다. 06은 선택 범위 계산/실패 격리, 07은 조회 선택과 전역 설정 분리, 08은 체크박스 UI, 09는 같은 선택의 관계 분석, 10~11은 통합 검증/운영 확인을 맡는다. 조건부 12도 선택을 고정해 사용하며 네이버 추정값을 이유로 이미 완료한 통합 조회 단계를 다시 막지 않는다.

필수 검증 사례는 전체 포함, 네이버만 제외, 쿠팡만 제외, 네이버만 포함, 광고만 선택, 판매만 선택, 전체 해제, 빠른 토글, 비교기간 동일 선택, 선택별 캐시 분리다. 네이버 숫자가 부정확한 업무상 추정값이어도 입력의 합계가 정확히 반영되는지, 네이버 장애/누락 상태에서 네이버를 빼면 다른 플랫폼 조회가 정상인지 확인한다. 5개 플랫폼의 32개 조합은 집계 계산 검증에 활용하고 UI는 대표 경계 시나리오로 확인한다.
