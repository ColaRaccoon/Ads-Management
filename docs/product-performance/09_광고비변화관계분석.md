# 09 광고비 변화 관계 분석

> 02단계 이후 필수 적용: [플랫폼 선택과 네이버 데이터 정책](플랫폼선택과네이버데이터정책.md). 이 추가 정책은 플랫폼 포함/제외·네이버 정확도에 한해 기존 전체 설계·공통 규칙·01 계약의 상충 문구보다 우선한다. 진행 중인 01 문서와 기록은 변경하지 않는다.

플랫폼 체크 상태를 결과 매출, 분석 대상 광고비, 시차별 표본과 전후 비교에 동일하게 적용한다. 제외한 네이버 데이터/품질 경고를 분석에 남기지 않는다. 선택 변경 뒤 숨은 광고 매체를 분석 대상으로 유지하지 않으며 선택 범위의 동반 변화를 설명한다.

## 목표와 선행 조건

매체별 광고비가 변한 시기에 제품 전체 매출이 얼마나 함께 변했는지 관측 관계를 보여준다. 08 DONE이 필요하다. 인과효과 모델은 조건부 12 범위다.

[시작 안내](00_시작안내.md), [공통 규칙](공통_작업규칙.md), 전체 설계의 7절, `records/01_확정계약.md`, `records/06_API계약.md`, `records/08_결과.md`를 읽는다.

## 이번 단계 작업

- 포함된 매체 중 분석 대상으로 선택한 광고비와 선택 판매처 합산 매출/광고 전 이익의 산점도, 시차별 관측 비교, 변경일 전후 일평균 비교를 구현한다. 모든 판매처를 포함한 때에만 제품 전체 매출이라고 표시한다.
- 같은 날·1·3·7·14일 시차에 필요한 조회 시작 전 구간을 추가 조회한다. 없는 날짜를 0으로 대체하지 않는다.
- 분석에 사용된 쌍의 수, 제외 일수, 기간, 변동성, 시차와 데이터 품질을 응답/화면에 표시한다.
- 01에서 확정한 최소 표본 정책을 적용한다. 잠정 60일 기준을 통계적 보장처럼 표현하지 않는다. 표본 부족·상수계열·누락 과다에는 계수를 숨기고 원인을 표시한다.
- 나머지 매체 비용, 행사·가격·품절·요일 등의 알려진 변화를 함께 볼 수 있게 한다. 없는 이벤트 데이터는 지어내지 않는다.
- 7일 이동평균은 시각화용으로 사용한다. 최적 시차 선택으로 효과 발생일을 단정하지 않는다.
- ‘광고비 증가 기간에 매출이 증가’라는 관측 문구를 사용한다. 순이익은 광고비를 직접 차감하므로 매출 효과와 구분한다.

## 필수 병렬 분담

서브에이전트 A는 시차/표본/전후 비교 계산과 검증, B는 API 기반 그래프/UI를 담당한다. 주 에이전트는 API 계약을 통합하고 독립 담당자가 통계 해석·표본 누출·결측 처리 오류를 검토한다.

## 완료 조건

알려진 관계를 가진 합성 시계열로 날짜 정렬과 시차 방향을 검증하고 실제 데이터의 사용/제외 일수를 대조한다. 표본 부족·상수·결측·동시 매체 변화에서 과도한 결론을 내리지 않아야 한다.

플랫폼 체크박스가 선택 범위 총이익과 분석 입력을 함께 바꾸고 API와 화면 설명이 일치해야 한다. 시차/분석 대상 지정이나 단순 범례 숨김은 플랫폼 선택 자체를 바꾸지 않는다. 네이버 추정값을 포함한 관측 분석은 가능하며, 표본 부족·계산 불가와 추정 표시를 구분한다. 12의 효과 추정이 없어도 사용자의 관측 관계 확인 요구를 충족해야 한다.

`records/09_결과.md`에 분석 정의, 제한 조건, 검증과 사용자에게 보여주는 표현을 기록한다.
