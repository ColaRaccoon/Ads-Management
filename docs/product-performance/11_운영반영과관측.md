# 11 운영 반영과 관측

## 목표와 선행 조건

검증한 기능을 운영에 반영하고 실제 제품 실적과 기존 업무를 확인한다. 10 DONE과 실행 가능한 배포/복구 계획이 필요하다. 이 단계 실행 지시의 운영 반영 범위 안에서 진행하며 과거 프로젝트 승인을 새 작업 승인으로 간주하지 않는다.

[시작 안내](00_시작안내.md), [공통 규칙](공통_작업규칙.md), `records/10_결과.md`, `records/10_배포복구계획.md`, 확정 계약과 현재 운영 기준선을 읽는다.

## 이번 단계 작업

- 배포 대상·현재 릴리스·DB·역할·수집 일정·기능 플래그와 복구 자료가 10단계 조건과 맞는지 확인한다. 차이가 있으면 영향을 재검증한다.
- 신규 모델/읽기 역할/배포를 정해진 순서로 적용한다. 권한 변경은 최소 범위로 하고 네이버 원천/공유 자격을 임의 변경하지 않는다.
- 기능은 OFF 상태에서 준비하고 대표 제품의 제한된 과거 집계를 만든다. 운영 데이터와 금액·완전성·제품명 자동 분류를 대조한 뒤 화면 노출을 진행한다.
- 필요한 집계 실행 정책을 적용한다. 기존 Meta·Google·Cafe24 수집 예약을 통합 조회 기능 때문에 중복 생성하거나 바꾸지 않는다.
- 실제 앱 권한, 제품별 KPI·그래프·설정 변경/재집계, 기존 플랫폼 화면, 최신 원천 반영과 운영 부하를 확인한다.
- 원천 갱신 이후 통합 집계가 갱신되는 실제 주기를 적어도 한 번 관측한다. 실패·재시도·복구는 격리 검증 결과와 운영에서 확인 가능한 상태를 구분한다.
- 중단/복귀 조건에 도달하면 계획대로 기능/집계 작업을 중지하고 기존 업무를 보존한다. 원천 삭제로 복구하지 않는다.

## 필수 병렬 분담

운영 변경 실행자는 주 에이전트 한 명으로 제한한다. 서브에이전트 A는 읽기 전용 금액·데이터 대조, B는 앱 동작·성능·권한 관측을 병렬 수행한다. 다른 에이전트가 독자적으로 배포·migration·재집계를 중복 실행하지 않는다.

## 완료 조건과 인계

실제 배포/적용된 항목, 제품별 계산·화면·기존 업무 결과, 최신 원천 반영 관측과 복귀 경로가 확인되어야 한다. 배포 성공과 운영 검증 성공을 구분한다.

미래 시각의 집계 관측이 남으면 IN_PROGRESS로 남기고 예정 시각·확인할 실행·판정 조건을 기록한다. 수동 실행을 정시 실행 관측으로 대신하지 않는다. 세션 종료 때문에 성공으로 바꾸지 않는다.

`records/11_결과.md`에 운영 버전, 적용 항목, 실제 관측, 알려진 한계, 운영/복구 방법을 기록하고 진행표를 갱신한다. 기존 과거 작업의 예약 관측이나 별도 미완료 작업을 이번 기능 완료에 섞지 않는다.
