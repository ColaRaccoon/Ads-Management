# 07 제품명과 배분 설정 화면

> 02단계 이후 필수 적용: [플랫폼 선택과 네이버 데이터 정책](플랫폼선택과네이버데이터정책.md). 이 추가 정책은 플랫폼 포함/제외·네이버 정확도에 한해 기존 전체 설계·공통 규칙·01 계약의 상충 문구보다 우선한다. 진행 중인 01 문서와 기록은 변경하지 않는다.

플랫폼 선택은 조회 사용자별 상태이며 전역 수집 설정이나 관리자용 이름/비용 규칙과 구분한다. 설정 화면의 미리보기에도 선택 범위를 전달할 경우 이를 명시하며, 체크박스 변경이 저장된 원천 비용 배분이나 규칙을 수정하지 않게 한다.

## 목표와 선행 조건

사용자가 고정 제품명, 판매단위, 이름 규칙, 비용 배분을 관리하고 자동 분류 결과를 확인하는 화면을 구현한다. 06 DONE이 필요하다.

[시작 안내](00_시작안내.md), [공통 규칙](공통_작업규칙.md), 전체 설계의 3·4·9절, `records/01_확정계약.md`, `records/02_결과.md`, `records/06_API계약.md`, `records/06_결과.md`와 웹 AGENTS.md를 읽는다.

## 이번 단계 작업

- `/products/mappings`에서 고정 기준 제품명과 이름 규칙을 표시한다. 기존 이름 규칙을 불러와 사용하고 ID 수동 등록 화면은 만들지 않는다.
- 이름 원문·인식된 제품·판매단위·사용 규칙·복수 후보/미분류 사유를 보여준다. 상품 ID 변경은 설정 작업으로 표시하지 않는다.
- 규칙 추가/수정 시 영향 제품·날짜·매출·광고비 미리보기를 보여주고 저장 후 영향 범위 재집계 상태를 표시한다.
- 단품·세트·옵션별 판매/비용 설정과 적용기간을 구분한다. 기존 비용 규칙을 손실 없이 확인할 수 있게 한다.
- 공통 광고비·배송·가구매 비용의 직접 귀속/배분/미배분을 구분한다. 배분 비중 총합과 0분모를 검증한다.
- 조회/관리 권한에 따른 버튼·서버 응답 처리를 구현한다. 중복 클릭과 동시 수정 충돌에서 유실을 막는다.
- 실제 관리 API에 연결한다. 임시 데이터로만 동작하는 화면을 완료로 처리하지 않는다.

## 필수 병렬 분담

서브에이전트 A는 이름 규칙/미리보기 UI, B는 판매단위·배분 UI를 맡는다. 주 에이전트가 공통 폼·API 타입·라우팅을 단독 통합한다. 별도 담당자가 권한, 충돌, ID 변경 시나리오를 검토한다.

## 완료 조건

같은 제품명으로 신규 상품 ID가 들어온 경우 사용자가 어떤 설정도 다시 하지 않고 자동 판정 결과를 확인할 수 있어야 한다. 이름이 모호한 경우에만 원인과 수정할 이름 규칙을 안내한다.

미리보기/저장/재집계 상태, 권한 거부, 검증 실패, 중복 저장, 규칙 변경 이력과 복구 시나리오를 실제 API로 확인한다. 기존 설정 화면이 유지되어야 한다.

`records/07_결과.md`에 화면 경로, 사용 API, 변경 소유 파일과 사용자 시나리오 검증을 기록한다. 통합 KPI 대시보드는 08 범위다.
