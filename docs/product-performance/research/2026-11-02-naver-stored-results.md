# 네이버 원래 프로그램의 저장 성과 사용

2026-11-02, `codex/performance-speedup` 시작점 `862f4bf`. 사용자는 별도 차이 분석보다 원래 네이버 프로그램에 저장된 성과를 그대로 읽는 수정을 명시적으로 요청했다. 기존 자사몰 수정은 완료됐고 이 문서는 네이버 후속 작업을 기록한다.

## 기준과 실제 저장 금액

원래 프로그램 `patima-naver-ss`는 `profit-v2`의 `daily_store_summaries`와 `daily_sales_unit_profits`를 저장한다. 저장 스토어 순이익에는 배송 손익이 포함돼 있고, 화면은 `daily_fake_purchases`를 한 번 추가 차감한다. 상품 순이익에는 이미 광고비·원가·수수료·부가세·기타 직접비가 반영돼 있다. 그룹의 `childRows`를 부모와 함께 합산하면 중복된다. 스토어 공통 광고 행은 실제 금액이므로 버리지 않는다.

실제 제한 worker 역할의 READ ONLY/RepeatableRead 조회로 11/1 두 허용 스토어의 저장 결과를 확인했다. 둘 다 profit-v2, COMPLETE이며 상품 합계와 스토어 매출·광고비·부가세 및 배송 포함 순이익이 일치한다.

| 스토어 순번 | 매출 | 저장 광고비 | 저장 순이익 |
|---|---:|---:|---:|
| 1 | 5,732,080 | 2,385,197 | 1,000,657 |
| 2 | 6,530,170 | 1,651,171 | 1,705,318 |
| 합계 | 12,262,250 | 4,036,368 | 2,705,975 |

직전 통합 화면 네이버 이익은 999,104원이었다. 이전 네이버 adapter는 저장 결과의 금액을 읽지 않고 원본 주문·원가 설정으로 별도 계산했다. 사용자의 지시에 따라 더 이상의 항목별 차이 원인 조사는 진행하지 않는다. [변경 전 저장값 대조](2026-11-02-naver-stored-before.json).

## 변경 계약

- 운영 네이버 worker는 저장 스토어/상품 성과, 배송 손익, 가구매와 스토어 타입만 읽는다. 주문·현재 원가·원본 광고 캠페인을 다시 조회하거나 계산하지 않는다.
- 저장 상품 순이익 + 저장 상품 광고비로 광고 전 이익을 표현하고, 통합 합계에서 같은 저장 광고비를 한 번 차감한다. 배송 손익과 가구매도 한 번만 반영한다. 이는 저장 결과를 기존 원장 형식으로 옮기는 연산이며 상품 원가 재계산이 아니다.
- 원래 프로그램이 성과에 포함한 광고비를 기준으로 한다. 제외된 광고를 통합 쪽에서 추가 차감하지 않는다. 따라서 순이익뿐 아니라 광고비·매출도 원래 프로그램과 같은 범위로 표시된다.
- 이름으로 제품을 분류하며 원본 ID는 출처·중복 확인에만 쓴다. 부모 그룹과 자식 내역을 중복 합산하지 않고, 미분류 공통 금액은 임의 제품에 붙이지 않는다.
- 저장 결과가 없거나 충돌하면 원본 주문으로 임의 재계산하지 않는다. 확인된 0과 미확정/null을 구분하며 검증 실패 시 기존 정상 발행을 보존한다.
- 자동 갱신 날짜 탐색도 저장 스토어/상품 성과의 날짜를 사용한다. 원래 프로그램에서 결과가 갱신되면 저장값 fingerprint 변경으로 통합 발행본이 갱신된다.
- 기존 GET은 저장된 통합 집계만 읽으며 네이버 원천 조회·재계산을 하지 않는다. DB 스키마나 역할 권한 변경은 필요하지 않다.
