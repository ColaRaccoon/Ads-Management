## 자동 갱신 구성

전용 비공개 Railway 서비스 `unified-performance-reconciliation` (`ca20108c-9ca1-41c4-a440-556416e18ba3`)를 기존 운영 프로젝트·환경에 추가했다. 환경 이름은 staging이지만 실제 서비스 운영 환경이다. 기존 웹·수집 서비스는 재배포하거나 변경하지 않았다.

- Dockerfile: `deploy/cloud/unified-reconciliation.Dockerfile`
- 실행: `node apps/api/dist/unified-performance/reconciliation-entrypoint.js`
- cron: `10 * * * *`, 매시간 10분. restart policy NEVER. 공개 도메인·HTTP listener 없음.
- 기존 `meta_ads_unified_worker` URL만 비밀값으로 전달. SSL 검증과 기존 CA 유지, DB 연결 1개. 제공자 토큰·웹 세션 키 없음.
- 원천 선택 기능 플래그와 네이버 허용 스토어 두 곳은 운영 웹과 동일하게 유지.
- 기본 한국시간 오늘까지 최근 7일과 미발행 과거 자료를 검사. 실제 원천 또는 확인된 0원 근거가 있는 날짜만 처리한다.
- 원천 fingerprint와 계산 버전이 같으면 재발행하지 않는다. 실패 시 기존 정상 발행을 보존하고 다음 시간대에 재시도한다.
- 처리 건수 기본 100, 실행 시간 기본 20분. 기존 대기 작업·최근 자료·과거 누락에 처리 몫을 나눈다.
- 최근 7일보다 오래된 이미 발행된 날짜의 원천 수정은 기존 명시적 재집계 경로로 처리한다. 정책상 사용할 수 없는 과거 원천이 누락 탐색 몫을 차지하면 날짜를 제한한 유지보수 실행이 필요할 수 있다.
