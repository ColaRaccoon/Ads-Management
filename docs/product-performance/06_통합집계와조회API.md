# 06 통합 집계와 조회 API

## 목표와 선행 조건

원천별 결과를 제품·날짜 기준으로 합치고 완전성, 비용 배분, 버전 발행, 기간 비교 API를 완성한다. 03·04·05가 모두 DONE이어야 한다.

[시작 안내](00_시작안내.md), [공통 규칙](공통_작업규칙.md), 전체 설계의 4·5·8·9절, `records/01_확정계약.md`, 02~05 결과에서 공통 타입과 어댑터 계약을 읽는다.

## 이번 단계 작업

- 판매와 광고 사실을 각각 제품·날짜로 먼저 집계한 뒤 결합한다. 판매처×광고매체 조인으로 금액이 늘어나지 않게 한다.
- 광고 전 이익·광고 후 추정이익·배분 전 제품이익을 구분하고, 공통비/배송수입 배분과 미배분 잔액을 보존한다.
- 적용 채널 범위와 수집/매핑/원가/환율 상태로 knownTotals와 completeTotals를 계산한다. 완전한 0과 미수집 null을 구분한다.
- 작은 계정·날짜 단위로 처리하는 집계 작업, 체크포인트, 멱등 키, 실행 중복 방지와 원자적 발행을 구현한다. 실패 시 이전 정상 결과와 stale 표시를 보존한다.
- 원천 교체·삭제·0건 정정·규칙/원가 소급 변경을 재집계한다. 최근 날짜 재대조와 명시적 과거 재집계를 지원하며 단순 updated_at 증분만 믿지 않는다.
- options, summary, timeseries, diagnostics, rebuild API를 구현한다. 관계 분석 API는 09가 맡는다.
- 일/주/월 합계와 비교기간의 금액·비중·증감률·%p·MER를 합계 기반으로 계산한다. 전기0·음수이익·부분기간을 처리한다.
- rebuild는 비동기 실행으로 제한하고 화면 조회가 원천 API/전체 JSONB 읽기/재집계를 시작하지 않게 한다.

## 필수 병렬 분담

서브에이전트 A는 집계/배분/비율 순수 계산, B는 작업 실행·발행·재계산을 담당한다. 주 에이전트는 API·공통 계약을 통합하고 권한·실패 복구 검토를 별도 담당자에게 맡긴다. 공유 repository/schema 변경은 단일 담당자만 한다.

## 완료 조건

실제 또는 승인된 익명 표본의 하루·7일·30일로 원천 총액 = 제품 배정액 + 미배분액을 대조한다. 원천별 어댑터 검증과 통합 대조를 혼동하지 않는다.

재실행, 중도 실패, 삭제/교체, 과거 비용 변경, 이름 규칙 변경, 없는 날짜, 0건 정정에 대해 중복·유실·부분 발행이 없어야 한다. 기간 비교와 주/월 합은 일별 합과 일치해야 한다. 권한과 범위 제한을 검사한다.

`records/06_API계약.md`에 요청/응답과 오류/품질 상태를 실제 구현대로 남긴다. `records/06_결과.md`에 집계 실행/재계산 방법과 대조 결과를 기록한다. 운영 예약은 이 단계에서 활성화하지 않는다.
