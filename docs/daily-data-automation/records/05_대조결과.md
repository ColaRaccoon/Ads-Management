- 대상: Google Ads `파티마그룹`, 고객 ID `139-159-2099`, KRW, `Asia/Seoul`
- 범위: 하루 `2026-09-29`, 최근 7일 `2026-09-23`~`2026-09-29` (모두 계정 현지 날짜)
- 환경: 로컬 전용 PostgreSQL `127.0.0.1:55433/phase03`, `meta_ads` schema. 운영 DB·배포·예약은 대상에서 제외.
- 상태: 실제 API 하루·최근 7일 읽기와 격리 DB 수집 성공. 화면 합계 대조 완료.

## 계정 식별과 인증

Google Ads 웹 계정 메뉴의 **선택된 고객**이 `파티마그룹 139-159-2099`임을 직접 확인했다. 기존 01 기록의 `849-685-2185`는 웹 주소의 `ocid=8496852185`를 고객 ID로 해석한 것으로, 실제 고객 ID가 아니다. 서비스 계정의 `customers:listAccessibleCustomers`는 `customers/1391592099` 한 건을 반환했고, 해당 고객의 `descriptiveName=파티마그룹`, `currencyCode=KRW`, `timeZone=Asia/Seoul`, `manager=false`를 실제 API에서 확인했다. 주소의 `ocid`로 Search하면 `CUSTOMER_NOT_FOUND`가 발생했다. 별도 manager 연결은 필요하지 않다.

인증은 Google 공식 라이브러리의 `adwords` scope와 로컬 ADC 서비스 계정 impersonation을 사용한다. 전용 서비스 계정은 광고계정 **읽기 전용** 사용자이며 키가 없다. Cloud 사용자에게는 해당 서비스 계정에 한정된 `Service Account Token Creator`가 부여됐고 IAM Service Account Credentials API가 활성화됐다. 장기 키·광고 쓰기 권한·프로젝트 전체 Token Creator는 만들지 않았다. `x-goog-user-project`를 넣은 첫 시도는 `USER_PROJECT_DENIED`였으므로 추가 Cloud IAM 권한 대신 이 헤더 없이 접근 가능한 Google Ads API 경로를 사용한다. 토큰과 ADC 파일 내용은 문서·로그·Git에 기록하지 않는다.

화면의 적용 필터는 `캠페인 상태: 사용 설정됨, 일시중지됨`과 `광고그룹 상태: 사용 설정됨, 일시중지됨`이며 삭제된 캠페인은 현재 보기에서 제외된다. 캠페인 표에는 `총 8개 중 1~8개`가 표시됐다. 별도 `campaign.status IN (ENABLED, PAUSED)` 메타데이터 Search에서도 8개가 반환됐고 모두 `PAUSED`였다(채널 DISPLAY 1, SEARCH 2, DEMAND_GEN 5; request ID `RCUl3Q3z6BYO-yfGGyLWxA`). 현재 계정에 PMax 캠페인은 없어 PMax 과거 비용은 합성 테스트로만 검증했다. GAQL은 지표가 전부 0인 캠페인 행을 생략할 수 있으므로 화면의 8개 0원 행과 날짜별 API 보고의 0행은 금액·노출·클릭 합계 관점에서 일치한다. Google Ads 보고 데이터는 재조회 시 변할 수 있으므로 화면·API는 같은 시점과 날짜·통화·필터로 대조했다. 0행은 모든 페이지·계정 합계 조회가 성공한 뒤에만 정상 0원으로 판정했다.

실계정 격리 실행은 `syncRun=ddfd79de-f998-4d20-9309-af77863fcfac`, 상태 `SUCCEEDED`, 계정 연결 `75db0720-0f96-486a-ab2c-242cc947c0df`였다. DB는 로컬 전용 `phase03/meta_ads`이며 7개 날짜의 current 캠페인 비용 행이 모두 0, coverage는 7건의 `COMPLETE_ZERO`다. 수집·게시 행 수는 모두 0이고 경고 코드는 없다. 화면의 0원은 반올림 차이가 아니라 API 원본 micros와도 정확히 0이다.
