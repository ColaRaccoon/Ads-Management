# 04 — 기존 계정 미지정 자료 귀속 계획 (미실행)

상태: **PLAN_ONLY**. 이 문서는 기존 CSV 업무 행의 계정 귀속을 검토하기 위한 절차다. 운영 DB와 격리 DB 모두에서 backfill을 실행하지 않았고, 행 건수나 충돌 수를 추정하지 않는다. `01_결과.md`의 단일 대상 계정 확인은 후보 계정을 고르는 근거일 뿐, 개별 행의 자동 귀속 승인은 아니다.

## 입력과 결과

- 입력: 검증된 `SourceConnection`의 provider·외부 계정 ID·shopKey·통화·시간대, 원본 CSV batch ID·기간·파일 해시, 기존 행의 내부 ID·정규화된 업무 키·현재 버전. Cafe24는 `Cafe24UploadBatch`/`Cafe24OrderLine`, Meta는 `UploadBatch`/`MetaCampaign`/`MetaAdset`/`MetaAd`와 두 일별 metric을 대상으로 한다. CSV 원문이나 `rawRow`는 내보내지 않는다.
- 사전 manifest: `manifestVersion`, 대상 connection ID, provider, 검증 근거 참조, 각 batch ID·기간·건수·해시, canonical key 충돌 건수, 승인자·승인 시각, manifest 자체 SHA-256. 실제 값은 보호된 작업 위치에만 저장한다.
- dry-run 출력: batch별 전체/후보/충돌/모호/미귀속 건수, 유일한 canonical key 해시 집합의 SHA-256, 기존 current·version 분포와 대상 계정의 기존 link 충돌 수. 고객 이름·전화·주소와 주문 원문은 출력하지 않는다.
- 모호한 자료는 별도 `UNRESOLVED` 목록에 내부 행 ID, batch ID, 사유 코드(`MULTIPLE_ACCOUNT_CANDIDATES`, `KEY_COLLISION`, `UNKNOWN_BATCH_SCOPE`, `LEGACY_NAME_ONLY`, `INCOMPLETE_BATCH`)만 기록한다. DB에서 기존 행의 `connectionId`는 `NULL`로 유지하고 `SourceRecordLink`를 만들지 않는다. 수동 검토가 끝나기 전 API 계정 범위 조회와 전환 대상에서 제외한다.

## dry-run 판정

1. 읽기 전용 격리 복제본에서 대상 DB fingerprint를 확인한다. 운영 접속 문자열을 로컬에 주입하지 않는다. 배치 원본의 기간·계정 근거와 기존 `SourceConnection`의 provider/통화/시간대가 모두 맞는지 검사한다.
2. Cafe24 업무 키는 `orderNo + lineOrderNo + productNo + optionName` 정규화 규칙을 적용한다. Meta의 ID 없는 CSV는 기존 synthetic/name key를 그대로 두고 확인된 단일 계정에만 후보 결속한다. 이름만 같은 API ID와 자동으로 합치지 않는다.
3. 동일 계정·kind·날짜의 기존 `SourceRecordLink` 및 API business key를 조회해 충돌을 분리한다. 광고와 광고세트 비용은 별개의 kind로 세고 합산하지 않는다. incomplete/FAILED batch, 버전 순서가 모호한 행, 원본 범위가 불명확한 행은 `UNRESOLVED`로 보낸다.
4. dry-run 결과의 batch별 건수·키 집합 해시와 manifest를 검토·승인한다. 이 단계에서는 `UPDATE`/`INSERT`/`DELETE`를 실행하지 않는다.

## 후속 실행 조건과 복구

승인된 manifest가 있고 격리 rehearsal에서 동일 건수·해시가 재현될 때에만 별도 변경 단계에서 chunk backfill을 설계한다. 각 chunk는 검토된 내부 ID 목록만 사용하고 `connectionId IS NULL` 및 예상 version/current 조건을 재확인한 뒤 `connectionId`와 CSV `SourceRecordLink`를 같은 짧은 트랜잭션에서 기록한다. 다른 값으로 이미 결속된 행이나 hash가 달라진 행은 중단하고 `UNRESOLVED`로 돌린다. 같은 manifest의 재실행은 멱등이어야 한다. API source 승격과 과거 CSV 삭제/복원은 이 backfill과 분리한다.

복구는 실행 manifest별로 새로 만든 link와 `connectionId` 변경 목록을 보존해 검토된 chunk만 역순으로 되돌리는 별도 transaction 계획으로 한다. 원본 batch, 업무 행, current/version, Storage 객체는 삭제하지 않는다. 실제 SQL·실행 결과·검증 건수는 실행 전 별도 기록이 필요하며 이 04단계에서는 없다.
