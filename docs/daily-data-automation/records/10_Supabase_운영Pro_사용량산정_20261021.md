## Egress와 디스크 시나리오

수집한 외부 API 응답은 Supabase 청구 Egress가 아니다. DB→앱의 조회 결과·checkpoint 재읽기 등은 Egress가 될 수 있다. [공식 Egress 설명](https://supabase.com/docs/guides/platform/manage-your-usage/egress)과 [DB 크기 설명](https://supabase.com/docs/guides/platform/database-size)의 구분을 따른다.

Cafe24 최대110회/일의 checkpoint 읽기를 계산한다. 기존 부분 checkpoint126,852B는 실제 전체 크기의 상한도 청구 wire byte도 아니다. 설정상 암호문16MiB 제한이 있어도 프로토콜 인코딩·다른 조회까지 모두 그 값으로 고정할 수 없다. 아래는 **회당 청구 wire1MiB 또는32MiB라는 민감도 가정**이며 실측 평균·완전한 상한이라고 표시하지 않는다. 기존 Pro 트래픽은 현재3.857GB를 경계 불명에 대비한20일로 나누어 나머지 날짜/31일에 연장했다. 이 연장도 향후 트래픽 보증은 아니다.

| 비캐시 Egress 시나리오 | 현재 주기 종료 총량 | 정상31일 총량 | Pro 포함량 |
|---|---:|---:|---:|
| 기존 속도 + checkpoint 회당1MiB | 약7.247 GB | 약9.554 GB | 250 GB |
| 기존 속도 + checkpoint 회당32MiB | 약46.579 GB | 약120.399 GB | 250 GB |

현재 사용량을 포함하며 정상31일에는 기존 트래픽 약5.978GB를 포함했다. 새 수집의 다른 DB 조회량·대시보드 횟수·외부 소비자 증가분은 개별 실측 계수가 없다. 큰 시나리오에서도 정상 약129.601GB의 여유가 있으나 이를 무제한 외부 트래픽 보장으로 바꾸지 않는다. 캐시 Egress 포함량은 비캐시 예산과 합치지 않는다.

디스크는 현재 총 사용0.99GB에서 시작하고, 모든 영구 저장 overhead를 포함해 논리 결과당8KiB/10KiB를 가정한다. 임시16MiB를 한번 더 예약하는 가정이며 MVCC·TOAST·동시 임시 쓰기까지 검증된 최대치는 아니다.

두 가정 모두 현재2GB 안에 들어가며 새 확장 실행에 의존하지 않는다. 저장 데이터는 누적되므로 이 결과를 무기한 적재 가능으로 해석하지 않는다. 기존 동일 인스턴스의 표시 단가0.01344달러/시간×744시간은 약9.999달러이며 UI의 월 compute credit10달러와 비슷하다. Usage는 Micro511시간/6.87달러, 설정은 legacy Nano 선택을 표시하므로 두 명칭이 같다고 단정하거나 정확한 청구서를 재구성하지 않는다. 기존 Pro 기본료·다른 유료 서비스·새 인스턴스 비용을 면제받았다는 뜻도 아니다.
