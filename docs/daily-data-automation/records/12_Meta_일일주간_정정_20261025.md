# Meta 일일 + 주간 수집 요구 정정 — 2026-10-25

상태: **IN_PROGRESS / 요구·계획 정정 완료, 코드·운영 예약 수정 미실행**. 현재 사용자 질문은 Meta 주간 전용 설정의 근거 확인과 일일 수집 요구의 정정이다. 이 기록은 수정 배포나 새 수집의 증거가 아니다.

사용자 직접 지시: “메타 광고비도 매일 수집되어야하고 플러스로 주간 수집인 구조지 주간수집만 이루어져선 안돼.” 이를 기존 Meta 주간 전용 문구보다 우선한다. 과거 문서가 '10/2 사용자 결정'이라고 적었다는 사실과 그 결정의 원래 대화 내용을 이번 세션에서 직접 검증했다는 주장은 구분한다.

## 현재 그렇게 작동하는 근거

- 공통_작업규칙, 00/02/08/09/11/12 계획과 records/02_확정계약에 Cafe24 일일, Google·Meta 주간 전용으로 적혀 있었다. 00은 매일 기존 업무를 대체한다고 하면서 Meta 수집은 주간으로 제한해 매일 광고비 확인 요구와 맞지 않았다.
- 실제 운영 영수증의 prod-meta는 anchor 10/31 02:02 KST, cadence_days=7, 단일 주간 일정이다. Meta 일일 일정은 없다.
- scheduled-occurrence.ts는 Meta interval=7일 / days=7을 고정하며 schedules()는 동일 connection의 두 일정을 거부한다.
- sync-contract.ts는 Meta scheduled run의 기간을7일로 제한하고 assertScheduledWindowCadence는 겹치는 성공 범위를 거부한다. 일일과 주간이 의도적으로 겹치는 구조를 현재 계약이 허용하지 않는다.
- scheduled-sync.service.ts는 Meta totalUnits/누락 날짜를7일로 고정한다. production-scheduler.sql도 connection/provider별 UNIQUE, prod-meta cadence7 CHECK 및 응답 기대 unit7을 강제한다.
- 따라서 변수나 cron 주기만 매일로 바꾸는 것으로 해결되지 않는다. 현재 코드·DB 예약관리 제약도 함께 바꿔야 한다.

## 정정한 목표

1. **일일:** 매일 완료된 전일 하루의 Meta 광고·광고세트 비용/필수 성과를 수집해 날짜별 마진 계산에 제공한다.
2. **주간 추가:** 매주 직전 완료 7일을 다시 조회·대조해 늦게 반영된 성과를 확인한다. 일일 수집을 대체하거나 광고비를 두 번 더하는 작업이 아니다. 매일 최근7일을 다시 읽거나 월 단위 자동 backfill로 확대하지 않는다.
3. 날짜·계정·광고/광고세트 식별자별 canonical version/current, 원본 통화·환율, 마지막 시도와 마지막 성공을 보존한다. 주간 오류가 이미 검증한 일일 데이터를 지우지 않게 한다. 광고와 광고세트 비용도 중복 합산하지 않는다.
4. 일일·주간 실행 키와 기간을 별도로 검증한다. 같은 계정의 동시 발행은 기존 리스/fencing으로 막고 일일 수집이 주간 작업에 밀려 누락되지 않도록 한다. 한 원천의 실패가 다른 예약을 막지 않게 한다.
5. Meta만 이번 정정 대상이다. Cafe24 완료 전일 일일 수집과 Google 기존 주간 계약, Storage 예약, 기존 자료를 보존한다. Meta 기존 읽기 권한·보호 자격을 사용하며 새 권한/발급을 계획 변경의 기본 전제로 삼지 않는다.

## 구현·검증할 범위

- 일정 정의에 일일/주간 목적과 주기·날짜 수를 명시하고, 허용된 Meta 한 계정에 두 일정을 안전하게 구분한다.
- foundation 기간·중복 범위/재시도 규칙, scheduled step/status/warnings, Meta runner의 하루/7일 실행 검증을 일치시킨다. 성공 코드만 맞추기 위해 범위 검증을 해제하지 않는다.
- 예약관리 표의 UNIQUE/CHECK, 발생 시각·재시도·응답 totalUnits/범위 검사를 수정한다. 기존 주간 실행과 감사 이력을 지우거나 과거 정시 성공을 새로 만들지 않는다.
- CSV/API canonical 선택과 재조회 시 version/current·매핑·환율·집계 중복이 없음을 실제 별도 DB에서 검증한다. 서로 다른 일일/주간 run이 같은 날짜를 읽는 의도적 중복과 같은 실행의 재전송을 구분한다.
- 화면의 정상 수집 주기·최근 성공·누락 경고, 운영 배포/복구 절차와 후속 관측도 일일+주간 기준으로 바꾼다. Meta 일일 연속3회와 주간 연속2회를 각각 관측하기 전 완료로 보고하지 않는다.
- 완료 날짜 단위의 조회량은 기존 주당7일에서 일일7일+주간7일=14일로 늘어난다. 실제 HTTP/MCP 요청수·paging·metadata·시간·사용량 증가는 별도 실측하며 이 계산을 금액 증가 추정으로 표현하지 않는다. 기존 포함량·권한·1GB/절전 제약을 확인하고 실제 추가 과금이 필요한 변경은 구체화한다.
