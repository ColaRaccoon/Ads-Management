# 단계별 증거 작성 안내
이 폴더는 각 구현 세션이 확정 계약과 실행 증거를 저장하는 위치다. 단계별 결과 파일의 상태와 증거를 기준으로 완료 여부를 판단한다.
필요한 최종 파일명은 각 단계 계획에 명시돼 있다. 존재하지 않는 결과 파일은 선행 단계가 미완료라는 뜻이다.

## NN_결과.md 양식
- 단계 / 상태 / 시작·종료 KST:
- 시작 SHA / 종료 SHA / 브랜치:
- 대상 환경 fingerprint(비밀값 제외):
- 구현한 내용과 변경 파일:
- 확정 또는 변경한 계약 / 변경 이유 / 후속 영향:
- 실행한 검증 명령 / exit code / 테스트 수 / 증거 경로:
- 실제 provider 계정 대조 범위 / 결과 / 아직 미검증인 항목:
- 운영 변경 여부(01~10은 없음):
- 남은 일 / 외부 의존 / 장애 / 재개 명령:
- 다음 세션이 먼저 할 3가지:

## 대조표 권장 열
provider, account의 비밀값 없는 별칭, 날짜, 계정 시간대·통화, 기여기간/보고시점, 원천 보고서 생성시각, API 조회시각, 항목, 원천 값, 앱 값, 차이, 원인, 판정.
고객 개인정보나 토큰을 첨부하지 않는다. fixture는 최소화·비식별화한다.

## 실정시 증거 권장 열
KST 예정일, provider/account 별칭, scheduler job, trigger 시각, app run ID, 완료 시각, 대상 날짜 범위, coverage, 수치 대조, 기존 업무 smoke, RSS/실행시간, 판정.
예약 등록 화면이나 수동 실행 캡처만으로 이 표의 성공을 채우지 않는다.
