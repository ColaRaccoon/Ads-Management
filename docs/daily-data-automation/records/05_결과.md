## 접근 경로와 공식 근거

구현일의 [Google Ads API 접근 정책](https://developers.google.com/google-ads/api/docs/api-policy/developer-token)을 확인했다. 2026-09-09 이후 developer token은 종료됐고 전용 Cloud 프로젝트의 Explorer 접근(프로덕션 2,880작업/일)을 확인했다. [서비스 계정 문서](https://developers.google.com/google-ads/api/docs/oauth/service-accounts)와 [Cloud impersonation 문서](https://docs.cloud.google.com/docs/authentication/use-service-account-impersonation)를 검토해, 광고계정에 이미 등록된 읽기 전용 서비스 계정을 **키 없이** 로컬 ADC에서 단기 impersonation하는 경로를 선택했다. 사용자 OAuth offline은 대안으로 검토했지만 현재 경로에서 필요하지 않았다. 외부 OAuth 동의 화면이 Testing인 경우 갱신 토큰 7일 제약도 있다. Google Ads Scripts→비공개 Sheets는 현재 직접 API 접근이 가능해 적용하지 않는다.

Cloud 계정에서 IAM Service Account Credentials API를 활성화하고, 사용자의 Cloud 계정에 전용 서비스 계정 한정 `Service Account Token Creator`를 부여했다. 전용 서비스 계정의 키는 계속 0개이며 광고계정 권한은 읽기 전용이다. 공식 Google Cloud CLI로 로컬 ADC impersonation을 설정했다. 저장 위치는 사용자 프로필의 Cloud SDK 자격증명 저장소이며 저장된 값은 확인·출력·복사하지 않았다. `x-goog-user-project` 헤더의 `USER_PROJECT_DENIED`에 대해 새 IAM 권한을 추가하지 않고 헤더 없이 Ads API를 검증했다.

실제 `customers:listAccessibleCustomers`는 `customers/1391592099` 한 건을 반환했다. Google Ads 화면의 선택된 고객도 `파티마그룹 139-159-2099`로 일치한다. 이전 01의 `849-685-2185`는 웹 주소의 `ocid`였고 실제 고객 ID가 아니다. 계정 메타데이터는 `KRW`/`Asia/Seoul`, 일반 고객(`manager=false`)이다. 자세한 기간·수치는 [대조 결과](05_대조결과.md)에 기록했다.

## 구현과 검증

Google Ads REST `v25`와 공식 `google-auth-library`를 사용한다. 계정 메타데이터, 서버가 검증한 날짜의 캠페인 일별 `campaign.id/name/advertising_channel_type`, `metrics.cost_micros/impressions/clicks`를 Search 모든 페이지에서 읽는다. 계정 수준 비용은 캠페인 합계 대조에만 사용한다. micros는 BigInt로 저장하고 요청·오류에는 안전한 진단 코드와 request ID만 남긴다. 성공한 완전 0행은 기존 current를 정리하고 coverage를 남긴다. 중간 페이지·권한·quota 실패는 publish하지 않는다. 최근 7일·지정 기간·전월 재조회는 공통 실행 계약을 쓴다.

## 범위와 남은 검증

실제 하루·최근 7일의 API→격리 DB→Google Ads 화면 대조는 완료했고 원본 micros도 정확히 0이므로 화면 반올림 잔차가 없다. JSON 경계는 `costMicros`·`impressions`·`clicks`를 십진 문자열로 직렬화하고 KRW 표시 금액을 BigInt로 한 번 반올림한다. 현재 05 범위에는 캠페인 행 공개 API가 없으므로 이 직렬화 유틸은 향후 공개 API가 사용할 준비된 경계다. 대상 계정에는 이 기간 양수 비용과 PMax 캠페인이 없어서 이 경우의 실계정 대조는 할 수 없었으며 합성 테스트로 검증했다. 수동 POST의 성공은 예약 실행 완료를 뜻하지 않는다.
