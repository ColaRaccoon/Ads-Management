`apps/api/src/daily-sync/`에 Graph `v26.0` `ads_read` client, 실제 읽기·CSV 비교 전용 CLI, Meta 실행 runner, 시스템 사용자 자격증명 참조 결속 서비스와 각 spec을 추가했다. `DailySyncController`/module에는 권한 분리된 `bind-meta-auth`와 `execute-meta`를 연결하고 route 권한 검사를 보완했다. `domain/meta-video-metrics.ts`, Meta 광고/광고세트 집계·읽기와 CSV 집계 경로, Web Meta 타입에서는 reach와 reach 기반 비율을 비가산 지표로 처리하도록 보정했다. 관련 spec도 수정했다.

수집 후보는 광고계정 ID·통화 USD·시간대 `Asia/Seoul`·허용 계정, 광고/광고세트 전체 페이지와 계정 합계, 액션 배열, 예상 기여 설정과 날짜별 광고 ID→결과 유형 지도를 검사한 뒤에만 04의 source policy·lease·canonical writer에 전달한다. 광고/광고세트 비용은 중복 합산하지 않으며 기존 CSV의 계정/원천별 current·version 선택을 유지한다. 비USD 계정은 `spendUsd` publish를 차단한다. 시스템 사용자 보호 참조·만료와 승인된 운영 티어 gate는 연결을 자동으로 READY/활성화하지 않는다. 실제 Meta 읽기에 사용한 **사용자** 토큰은 이 운영 자격 조건의 증거가 아니다.

신규 migration `apps/api/prisma/migrations/20260930160000_meta_nonadditive_reach/migration.sql`은 `MetaAdsetDailyMetric.reach`의 NOT NULL/default를 제거한다. 여러 광고/일자를 합칠 때 reach·frequency 또는 reach 기반 비율을 더하거나 0으로 꾸며 보여주지 않고 `null`로 표시하기 위한 nullable 변경이다. 기존 행은 재작성하지 않으며 기존 다중 광고 CSV 광고세트 행의 원시 합산 reach/frequency는 `/metrics/unmatched` 조회 투영에서도 `null`로 가린다. Prisma schema 검증만 수행했고 **로컬 격리 DB에도 migration을 적용하지 않았다**. 02 계약의 원천 선택·버전·통화 원칙과 04의 canonical 저장 경계를 유지한다. 07 계획의 비가산 의미에 맞춰 기존 CSV 집계의 표시 의미를 보정했으며, 이 영향은 관련 기존 테스트까지 독립 회귀했다.

## 실제 읽기와 대조

[07 대조 결과](07_대조결과.md)에 파일 fingerprint, 요청 조건, 동일 시점 지표, ID별 검사, 후속 시점 차이, 액션/영상/결과·기여 설정의 미확정 범위를 기록했다. 광고 관리자에서 새로 내보낸 `2026-09-29` 광고 수준 CSV의 지출 양수 70개 광고와 같은 날짜 API 광고 70개는 ID별 지출·노출·링크 클릭이 70/70 일치했다. 합계는 USD `3,776.41`, 노출 `275,433`, 링크 클릭 `5,380`이다. 이후 CLI 재조회는 광고 77행 중 지출 양수 70행을 비교했고, 이전 CSV와 광고 1개의 지출 USD `0.01`·노출 1 차이가 생겼다. 이는 **시간이 다른 읽기**이므로 완전 일치라고 판정하지 않았다. 오전의 같은 날짜 CSV와 오후 CSV 사이에도 USD `0.42`·노출 38·링크 클릭 3의 차이가 있어 과거일 보정 필요성을 확인했다. 변동 원인은 미확정이다.

실제 계정의 `actions`·영상·광고/캠페인/광고세트 metadata 표본을 읽었다. 그러나 `shop_clicks`는 성공 응답에서 필드가 빠졌고, CSV의 결과 표시 도구는 복수 유형이며 기여 설정/보고 시각 원문 열이 없다. 구매 action 별칭을 합산하지 않고, 누락 필드·빈 셀을 검증된 0으로 대체하지 않는다. 이 조건에서 자동 publish를 허용할 필수 지표와 표시 계약은 확정하지 않았다. 전체 metadata/adset 페이지·ID 결합, 실제 current/version 저장·재수집·빈/부분 페이지 처리, 02:30 지연과 실제 사용량은 미검증이다. 운영 DB나 격리 DB에 Meta 실응답을 적재하지 않았다.

## 접근·외부 조건

Graph API Explorer에서 기존 **사용자** 토큰에 `ads_read` 한 권한만 표시됐다. 앱 화면의 `ads_read`는 테스트 준비 완료, Marketing API Access Tier는 **Limited**다. `ads_management`를 요청하지 않았다. 기존 시스템 사용자에게 대상 광고계정 자산이 없고, 앱은 미게시·비즈니스 미인증이다. 대상 자산 할당, 앱 설치와 기간·갱신/철회가 확인된 시스템 사용자 토큰, Limited에서 이 내부 정기 수집을 허용하는지 또는 Full/심사가 필요한지, 호출량 적합성은 미확정이다. 기존 Meta 담당자의 API 자체 별도 비용 없음 답변은 유지하되 별도 계약·최소 결제에 대한 명시 답변은 아직 없다.

단회 CLI의 첫 실행은 Graph 계정 ID의 `act_` 접두사 처리, 두 번째는 `v26.0`에서 지원되지 않는 3초 영상 필드 요청으로 실패했다. 개발자가 두 결함을 수정하고 회귀 테스트를 추가했으며 세 번째 실제 실행은 exit 0이었다. 토큰은 일시적인 localhost 수신기를 거쳐 CLI 자식 프로세스 메모리로만 전달했다. 원문 토큰·광고명·CSV 행은 Git, 문서, fixture, DB, 로그에 기록하지 않았다. 수신기를 종료하고 포트 종료를 확인했다. 보호 저장소의 지속 token을 생성하거나 연결하지 않았다.

## 검증과 독립 평가

개발자와 독립 평가자가 코드 수정·재검토를 수행했다. 평가자는 기존 기능 회귀, API/CSV의 수집·저장 흐름, 중복 비용, 비가산 지표, 불필요한 함수, 스타일·유지보수성, 권한/실패 경계를 검토했다. `act_` 계정 ID, v26.0 3초 영상 필드, 지출 0·늦은 활동, 단일 결과 유형 가정, action 부분 누락·정상 0일, 날짜별 결과 지도, 비USD 저장, CSV/API reach와 `/metrics/unmatched` 구행 노출, 오래된 테스트 기대값을 개발자에게 돌려 수정·재검토했다. **최종 검토 범위의 미해결 코드 결함은 0건**이다.

## 남은 일과 재개 순서

1. 대상 광고계정 자산을 어떤 전용 시스템 사용자에 할당할지, 앱 설치·`ads_read` 최소 권한과 지속 토큰의 보호 보관·갱신/철회 절차를 계정 소유자가 결정하고 수행한다. 이 단계에서는 수행하지 않았다.
2. Meta 공식 지원/앱 심사 경로에서 Limited의 자사 계정 내부 정기 수집 허용 범위, 필요한 Full tier·비즈니스 인증, 별도 계약/최소 결제를 명시 확인한다. 실제 페이지 수·재조회/재시도 계획으로 quota/지연을 측정한다.
3. 결과 표시 도구·기여/보고 시각·`shop_clicks`의 대체/nullable 계약을 확정하고 광고세트/metadata 전체 페이지, 동일 기간 격리 DB publish·version/current·중복 비용·명시적 동일일 재실행을 검증한다. 2026-10-02 비용 결정에 따른 **7일마다 직전 완료 7일**의 호출량·지연과 늦은 전환의 미보정 한계를 실측한다. 필요한 비동기 report job은 해당 주간 범위에서만 저장·재개하며 장기/월 보정은 구현하지 않는다.

재현은 승인된 사용자 토큰을 **환경변수 값이나 명령행에 출력하지 않는** 단회 경로로 제공한다. `apps/api`에서 `node --import tsx src/daily-sync/meta-isolated-verify.cli.ts`를 실행하며 자식 프로세스 전용 환경에 `META_VERIFICATION_ACCOUNT_ID`, `META_VERIFICATION_DAY`, `META_VERIFICATION_CSV`, `DAILY_SYNC_META_ACCESS_TOKEN`, `DAILY_SYNC_META_ACTION_REPORT_TIME`, `DAILY_SYNC_META_ATTRIBUTION_WINDOWS`를 전달한다. 토큰을 디스크 `.env`나 셸 히스토리에 쓰지 않는다. 코드 검증은 `npm --prefix apps/api test -- <관련 spec 경로>`, `npm --prefix apps/api run lint`, `npm --prefix apps/web run lint`, `npm --prefix apps/api run prisma:validate`, `git diff --check`를 사용한다. 운영 DB·배포·변수·예약은 건드리지 않았고 08은 시작하지 않았다.

## 2026-10-02 비용 주기 변경

07의 과거 단회 대조 결과는 보존한다. 사용자 결정에 따라 Meta 자동 예약은 **7일마다 한 번**, 광고계정 현지시간 기준 직전 완료 7일을 날짜별로 한 번씩 읽는다. 기여/보고 지연에 따른 이전 기간 반복 조회·월 보정·자동 누락 복구는 계획에서 제거했다. 뒤늦은 전환·비용 수정은 자동 보정되지 않는다는 한계와 마지막 성공/누락 표시, 관리자가 날짜를 명시한 수동 하루 재실행을 07/08 검증 항목으로 둔다. 결과 지표가 이 시점 고정 정책에서 업무상 허용되는지와 주간 tier·quota는 미확정이며 07 **BLOCKED**를 유지한다. 운영 예약은 만들지 않았다.
Meta runner는 잘못된 주간 범위를 provider GET 전에 거부하도록 로컬 보완했고 독립 평가의 공통 집중 50/50·lint에서 미해결 P1/P2가 없었다. 이는 07의 원래 실적재·자격 차단 조건을 해소한 결과가 아니며, 08 예약·운영 배포는 하지 않았다.
