# Google 원 승인 계정과 현재 표시 권한 확인

2026-10-21 KST 기준, Google OAuth 원 승인 계정을 기존 기록·연결된 Gmail·Google 승인 알림으로 교차 확인했고, 사용자가 직접 읽어 제공한 현재 화면의 권한 전체 문구도 확보했다. **원 사용자 경위와 현재 표시 승인 범위의 읽기 조사는 완료**다. Google grant의 실제 철회·외부 소비자 전환·옛 자격 거절 검증은 실행하지 않았으므로 공유 자격 NO-GO 조건 전체가 해소된 것은 아니다.

이 기록은 [원 설정 경위](10_Google_OAuth_설정경위_20261021.md)의 당시 계정·표시명·현재 범위 미확정 부분을 아래 증거 범위에서 갱신한다. 이전 문서와 영수증은 당시 이력으로 보존한다.

## 사용자가 확인한 현재 표시 권한

사용자는 같은 계정의 Google Auth Library 세부정보 확인 요청에 대해 연결 날짜와 다음 권한 전체 문구를 회신했다. 현재 화면 내용의 출처는 **사용자 직접 확인 회신**이며, 에이전트가 화면을 직접 열어 관측한 것으로 표시하지 않는다. 회신 수신일은2026-10-21 KST이고 실제 화면 조회 시각은 별도 제공되지 않았다.

> Google Cloud 데이터 확인, 수정, 구성, 삭제 및 Google 계정의 이메일 주소 확인

세부 설명은 BigQuery 테이블·데이터 세트·작업, Compute Engine 인스턴스, Cloud SQL 인스턴스, Datastore 데이터, Cloud Storage 데이터, Google Cloud 운영 제품군 모니터링 데이터와 Cloud 리소스의 확인·변경을 포함했다. 이메일 주소 확인도 표시됐다. 회신에 포함된 `pentagon`은 아이콘 설명으로 보고 OAuth scope로 분류하지 않는다.

[Google 공식 scope 목록](https://developers.google.com/identity/protocols/oauth2/scopes)은 이 권한 설명을 `https://www.googleapis.com/auth/cloud-platform`에 대응시킨다. 원 발급 응답에서 확인한 scope와 현재 표시 문구가 일치한다. **이 OAuth 승인 범위는 읽기 전용이 아니며 Cloud 데이터 수정·구성·삭제까지 포함한다.** 이메일 주소 확인이 이 scope 설명 자체에 포함되므로 이 문구만으로 별도 `userinfo.email` scope가 추가됐다고 표시하지 않는다.

실제 자원에 수행 가능한 작업은 해당 주체의 IAM 등 자원 권한에도 제한된다. [Google의 IAM과 scope 설명](https://docs.cloud.google.com/compute/docs/access/service-accounts#authorization)은 두 권한 경계를 구분한다. 과거 Ads 읽기 전용 서비스 계정의 업무 권한과 원 사용자 source OAuth 승인 범위를 같은 것으로 취급하지 않는다. 이번에는 현재 IAM 전체나 다른 자원 접근을 새로 조회·변경하지 않았다.

## 확인 완료와 남은 범위

| 항목 | 현재 판정 |
|---|---|
| 원 설정 세션·기본 ADC client·원 source refresh 결속 | 기존 정확 일치 증거를 재사용한다. |
| 원 승인 계정 | 기록 계정·Gmail 계정·Google 승인 알림의 수신 계정과 시각으로 교차 확인 완료다. |
| 화면 앱 표시명 | Google 승인 알림과 사용자 회신으로 **Google Auth Library**를 확인했다. |
| 현재 화면에 표시된 권한 | 사용자 회신으로 확보했고 공식 scope 설명과 대조 완료다. 화면 전체 권한 문구에 대응하는 범위는 `cloud-platform`이다. |
| 기술적 전체 scope URI 목록·token subject | live introspection을 하지 않았다. 화면 문구에서 scope를 대응한 것과 구분한다. 이 조사에 추가 발급·refresh를 요구하지 않는다. |
| 기존 refresh/access의 현재 유효성 | 시험하지 않았다. 현재 UI에 권한이 표시된다는 사실을 정확한 token의 유효성 검증으로 확대하지 않는다. |
| 외부 소비자·실제 처분 | 같은 기본 ADC grant를 쓰는 다른 기기·도구 전체, 실제 grant 철회와 옛 자격 거절·대체 정상 검증은 남아 있다. |

사용자는 이번 읽기 확인에 필요한 날짜와 권한 문구를 이미 제공했다. **추가로 직접 해야 할 확인은 없다.** 향후 실제 공유 자격 처분을 결정할 때만 조사 범위 밖의 같은 ADC 사용 여부, 전환·중단 시점과 철회 범위를 보완하고 필요한 본인 로그인/MFA를 수행하면 된다. 지금 연결 삭제·철회·재승인은 하지 않는다. 서비스 계정 IAM 변경이나 ADC 파일 삭제로 원 grant 처분을 대신하지 않는 기준도 유지한다.

## 접근 한계와 증거 보존

CUA inventory는 이번에 성공했고 in-app browser와 MCP Apps만 나타났다. 기존 Chrome 연결은 제공되지 않았다. native 창 조회는 Chrome1개를 찾았으나 현재 URL을 안전하게 판별할 수 없다는 도구 정책으로 상태 읽기가 차단됐다. 그 뒤 UI 입력을 중단했다. 따라서 직접 브라우저 화면 검증은 수행하지 않았고 현재 표시 권한은 사용자 회신으로 보완했다.

대안인 [Workspace Directory tokens.list](https://developers.google.com/workspace/admin/directory/reference/rest/v1/tokens/list)는 `admin.directory.user.security` scope가 필요한 별도 관리 API다. 현재 연결 도구에는 해당 grant 목록 기능이 없으며, 이를 위해 새 scope·관리자 권한·토큰을 요청하거나 발급하지 않았다. 계정에 관리자 권한이 없다고 단정하지 않는다.

새 증거 폴더는 `C:/Users/seong/AppData/Local/MetaAdsPhase10Evaluation/continuation-20261021/google-grant-identity-read-v1/`이다. `identity.json`은 사용자 권한 회신 전의 읽기 snapshot이고 `closeout.json`이 사용자 회신을 반영한 최종 상태다. 원 Gmail 본문·헤더 전체·계정 식별정보·인증 응답은 저장하지 않고 메시지 ID·시각·일치 여부와 비민감 권한 문구만 남긴다. 기존 ADC·원 로그인 로그와 이전 문서·영수증의 해시를 보존했다.

**이번 조사 대상 자격 발급·refresh·교체·철회0, OAuth 재승인0, IAM·운영 변경0, 외부 메시지0, 새 로그인0,11·12 미착수**다. 기존 검사·빌드·격리 검증을 반복하지 않았다. 운영 NO-GO와 다른 공유 자격·Supabase 조직 사용량의 미해결 상태, Free 플랜과 정확20바이트 CDN의 EXCLUDED_LIMITATION을 유지한다.
