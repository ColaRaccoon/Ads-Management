## 구현·검증

### 코드 경계

- `Cafe24CanonicalPersistence`와 `MetaMetricVersionService`에 기존 CSV의 현재 버전 전환·정규화 저장을 모았다. CSV의 파일 검증/파싱·파일 hash·원본 Storage 생명주기는 기존 업로드 경로에 두고, 정규화된 API 레코드는 `CanonicalApiWriterService`가 파일 참조 없이 같은 업무 테이블에 기록한다. API 행은 `syncRunId`/계정/원천/수정 시각 또는 revision을 가지며 업로드 배치·행·`rawRow`는 없다.
- `CanonicalApiWriterService`는 source policy와 lease fence 아래 Meta 광고/광고세트, Cafe24 주문을 publish한다. Cafe24 변경 구간은 먼저 모든 interval unit을 계획하고 각 구간을 별도 checkpoint로 처리한다. 전체 날짜 snapshot은 누락된 현행 주문이 있으면 publish 전에 거부한다. Meta 광고 소재 파싱·Creative/Alias/Placement와 광고세트 집계도 CSV 규칙을 공유한다.
- CSV/API의 현재 포인터·version·중복키를 계정과 원천별로 분리했다. 조회는 `SourcePolicy`의 계정/날짜/종류별 선택 원천을 적용한다. 미귀속 기존 CSV 현재 행이 가려질 수 있는 정책 생성·업로드는 실패로 처리하고, 모호한 이름만으로 계정을 자동 귀속하지 않는다. Meta 소재·광고세트 엔터티와 CSV 복원은 계정 범위로 한정했다.
- 기능 플래그를 끈 rollback 읽기는 이미 계정에 연결된 행까지 CSV만 투영한다. 정책이나 계정 귀속 current가 남아 있는 날짜의 새 **미귀속** CSV 업로드는 중복 KPI를 막기 위해 `SOURCE_SELECTION_REQUIRED`로 거부한다. 그 날짜의 수동 CSV 재수입은 계정 귀속 검토와 원천 정책 전환 절차를 거친 뒤 재개해야 한다.
- `20260929170000_canonical_import_origins`는 기존 업무 테이블에 nullable 계정/run 필드, API 원천 CHECK, source/account별 현재·version partial unique 인덱스를 추가한다. `20260930093000_meta_action_report_time`은 Meta 광고/광고세트의 attribution 보고 설정을 nullable로 추가해 기존 CSV 행을 보존한다. 두 migration 모두 격리 로컬 DB에만 적용했다.

주요 변경 위치: `apps/api/src/daily-sync/`의 canonical 저장·API writer·원천 정책·실행 기반, `apps/api/src/uploads/`의 Meta CSV/버전/소재/원본 생명주기, `apps/api/src/sales/`의 Cafe24 CSV/매출 조회, `apps/api/src/common/source-read-policy.ts`, Meta 조회/매핑/변경로그 서비스, Prisma schema와 위 두 migration 및 각 회귀 spec이다. 02의 원천 선택·변경창·버전 계약은 유지했다. 원래 Meta 스키마에 없던 `actionReportTime` 필드는 동일 attribution/reporting 설정의 완전한 API 일일 검증·버전 비교에 필요해 nullable additive 필드로 보완했다. 외부 API 원문 필드명을 확정한 것은 아니며 정규화 어댑터는 07에서 검증해야 한다.

기존 Cafe24/Meta 테스트 입력을 그대로 사용한 사전·사후 회귀와 합성 정규화 API 입력으로 검증했다. 실제 원본 CSV는 동일성 증명에 필요하지 않았다. 개인정보가 포함된 원본을 열람하거나 문서/Git에 복사하지 않았다. 로컬 DB는 `127.0.0.1:55433 / phase03 / meta_ads` 전용 컨테이너이며 운영 Supabase 연결을 사용하지 않았다. 실제 provider 호출·실계정 수치 대조는 **0건**이다.

개발자 구현 후 평가자가 기존 기능 회귀, CSV/API 데이터 흐름, 코드 스타일·유지보수성, 저장·복원·권한 경계를 독립 검토했다. 초기 검토에서 발견한 정책/매핑 겹침, Cafe24 변경창·coverage, Meta 소재·backfill·엔터티 관측일 등의 결함은 개발자 수정과 평가자 재검토를 반복해 닫았다. 평가자 최종 집중 회귀 **110/110 통과**, **미해결 04 코드 결함 없음**. 원본 Storage pending/restore/purge, SKIP/overwrite/실패 재시도, 상품/쿠폰 매칭, current/version 전환, 감사·HTTP 권한은 전체 회귀에 포함됐다. API 부분 publish 실패와 source-off rollback은 기존 성공 CSV current를 보존하는 별도 spec으로 확인했다.

격리 DB의 새 `meta_ads_stg_runtime` 역할은 03 신규 10개 테이블에만 권한이 있고 구 업무 테이블에는 권한이 없다(`source_connections` SELECT=true, `cafe24_order_lines` SELECT=false). 새 테이블에서 anon/authenticated SELECT는 false다. 이 합성 역할로 구 업무 테이블 쓰기까지 통합 실행했다고 주장하지 않는다. 실제 앱 runtime 역할의 변경된 구 테이블 읽기/쓰기와 Data API 차단은 10/11 운영 게이트에서 확인한다.
