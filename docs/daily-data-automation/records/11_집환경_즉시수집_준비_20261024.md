## 최신 사용자 승인

사용자는 기존 발급·refresh 금지에서 진행을 멈춘 설명을 받은 뒤, 자동 수집에 필요한 자격·연결·설정 작업을 승인하고 02:00을 기다리지 않는 즉시 시험 수집을 요청했다. 이어 Cafe24 운영 연결 준비 경로에 필요한 **최소 코드 수정도 포함해 진행**한다고 명시 승인했다. 따라서 앞선 재개 문서의 발급·refresh 전면 금지는 이번에 필요한 범위에서 해제됐다. 과거 자격 복원, 권한 확대, 다른 날짜 자동 backfill, 기존 C7 migration 반복은 승인 범위에 포함하지 않는다.

## 코드 변경과 검증

- 수집을 OFF로 둔 채 관리자 권한으로 비활성 연결 생성·목록·기존 보호 자격 바인딩·Cafe24 정상 OAuth를 준비하는 별도 스위치를 추가했다. 기존 공급자 조회·검증·실행에는 기존 feature guard를 유지한다.
- Cafe24 정상 OAuth로 READY가 된 연결에만 만료·암호문 AAD·갱신 잠금·revision·updatedAt CAS·기존 데이터 충돌 검사를 거쳐 CSV 기본 정책과 shadow 수집 준비를 원자적으로 만든다. 감사 기록 실패도 transaction 전체를 취소한다. READY 강제 변경이나 공급자 요청은 하지 않는다.
- Cafe24의 기존 일일 원천 활성화 검사를 `settings.manage` API로 노출했다. 성공 run·coverage·검토 snapshot을 기존 서비스가 다시 검사하므로 수집 성공 전에는 활성화할 수 없다.
- 기존 C7 launch와 웹은 보존한다. 추가 시작 스크립트는 정확한 운영 Railway/DB 대상에서만 Google keyless impersonation ADC와 Meta 암호화 envelope/스키마를 비공개 RAM 파일로 준비한다. 원문을 기록하거나 웹 프로세스에 전달하지 않고 종료 시 생성한 경로만 삭제한다.
- Docker 이미지는 기존 C7 digest `sha256:e3fb7eedf91ef64d6c26590856d2c979e5644b644109d4fb9549ad8ad66fa964`를 기반으로 한다. API 273개 JS 비교에서 승인된 9개 파일 외 차이가 없다는 검사를 이미지 빌드에 포함했다. DB schema·migration·기존 Prisma runtime·웹 산출물은 바꾸지 않는다.

검증: API TypeScript 검사/빌드 PASS, 새 준비 테스트 3개 PASS(실제 loopback PostgreSQL의 만료·갱신 소유자·다른 AAD·stale revision/CAS·CSV 충돌·감사 실패 rollback·동시 1건 성공), 시작 스크립트 테스트 2개 PASS(Windows와 비 root Linux 컨테이너에서 각각 같은 2개), 컴파일된 신규 경로 4개의 settings.manage metadata 검사 PASS, C7 파일 비교 273개/변경9개 PASS, Docker 빌드 PASS. 실제 provider 요청이나 운영 수집을 이 로컬 검증으로 세지 않는다.
