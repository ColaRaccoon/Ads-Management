격리 10/1 한 주문의 shape-only 진단에서 최상위 `order_price_amount`는 부재, `payment_method`는 배열이며 `actual_order_amount`와 `initial_order_amount`는 객체였다. 두 객체의 허용된 `order_price_amount`, `payment_amount`, 할인·쿠폰·배송비 등 13개 금액 키는 모두 문자열 타입이었다. 한 주문의 타입 증거이므로 해당 중첩 금액이 CSV `총 주문금액`과 같거나 최종/초기 금액 중 어느 쪽이 기존 계산 입력인지는 아직 확정하지 않는다. 값·임의 키·주문 식별자는 출력하지 않았다. 같은 날 결제액 3/422 차이와 결제수단 코드→CSV 라벨/쿠폰 판정, 금액 필드 의미, 실제 canonical 발행·복구는 남아 있어 **06 BLOCKED**다.

같은 배포의 날짜 HMAC 재실행에서는 `발주일`이 있는 **419주문**의 한국 날짜가 API `order_date`와 **419/419** 일치했다. 정확한 시각은 적어도 한 CSV 시각과 **388/419**, 모든 CSV 시각과 **387/419** 일치했다. 같은 주문의 CSV 시각이 둘인 주문은 1건이다. ### 실제 PostgreSQL 합성 발행 대조의 범위

별도 로컬 PostgreSQL 17.10의 빈 합성 DB에 전체 migration 45개를 적용한 뒤, 합성 하루의 CSV current→API shadow→명시 전환→불변/변경 수동 재실행→중간 실패 복구 테스트 **1/1**이 통과했다. 독립 읽기 검사에서 CSV current 1행, API current 1행과 history 1행, API version 1 비현재·version 2 현재, current link/version 2, 실패한 마지막 시도와 구분된 마지막 성공이 보존됐다.
