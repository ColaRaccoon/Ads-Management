# 모든 단계의 공통 계약
이 문서는 각 세션의 필수 읽기다. 현재 사용자 지시와 실제 적용 AGENTS.md가 우선한다. 이 계획은 구현·운영 변경을 이미 수행했다는 기록이 아니다.

## 운영 보호
- 01~10에서 운영 코드 배포·운영 DB 마이그레이션·운영 수집 적재·운영 예약 등록을 하지 않는다. feature off라도 새 코드를 운영에 미리 배포하지 않는다.
- Git 작업 전 HEAD/status와 적용 AGENTS.md를 확인한다. 기존 수정과 구글 원본 계획을 보존한다. 기능 작업은 codex/ 브랜치와 격리 체크아웃을 사용하고 실제 자동 배포 브랜치에 push하지 않는다.
- staging/test DB·Auth·Storage·예약·비밀값은 운영과 분리한다. 개발 환경에 운영 DATABASE_URL을 넣지 않는다. 실계정 API는 허용된 읽기만 하고 결과는 격리 DB로 보낸다. 테스트 수신자의 권한·quota 영향도 제한한다.
- 운영 보호 비밀값 변경 자체가 재배포를 유발할 수 있다. 11 전에는 운영 Railway 변수도 바꾸지 않는다. 기존 Storage 갱신 일정과 배포를 가로채거나 중지하지 않는다.
- 실제 운영은 deploy/cloud/README.md가 우선이다. deploy/local·windows·구 compose.staging은 역사 자료이므로 그대로 운영 절차에 쓰지 않는다. 환경명이 staging인 것만 믿지 말고 DB/Storage/project 연결 대상을 검증한다.
- 확인된 사용자 승인을 다시 요구하지 않는다. 구현 요청의 범위 내 가역 작업은 진행한다. 운영 반영·유료 전환이 승인 범위를 벗어나면 완성된 릴리스와 변경 내역을 제시한 후 필요한 마지막 승인만 받는다. 권한 부족을 테스트 성공으로 대체하지 않는다.

## 비용·자격
Google 원본의 추가 비용 최소화 조건을 유지한다. 신규 유료 커넥터·Redis·상시 worker·새 DB를 기본 도입하지 않는다. 기존 포함량 내인지 확인한다. 실제 추가 과금 예상 시 비용 영향과 대안을 먼저 구체화한다.
**2026-10-25 사용자 정정이 최신 수집 계약이다.** Cafe24는 매일 몰 현지 기준 완료된 전일 하루, **Meta는 매일 계정 현지 기준 완료된 전일 하루 + 매주 직전 완료 7일의 추가 재조회·대조**를 수행한다. Meta 주간 수집은 일일 수집을 대신하지 않는다. 동일 날짜의 주간 재조회는 검증된 canonical version/current를 갱신하며 광고비를 중복 합산하지 않는다. Google의 기존 7일마다 직전 완료 7일 계약은 이번 Meta 정정의 변경 대상이 아니다. Meta 주간 범위를 벗어난 자동 과거/월 순환·누락일 따라잡기는 추가하지 않는다. 실패한 동일 범위의 제한 재시도와 관리자가 날짜 하나를 명시한 수동 복구 원칙은 유지한다. 매주 7일의 추가 재조회 밖에서 발생한 늦은 변경은 자동 반영을 보장하지 않으며 마지막 성공 시각·누락 날짜·수집 시점의 수치를 표시한다.
현재 배포ca939ed와 운영 Meta 예약은 아직 주간 전용이다. 이 문서 정정만으로 일일 예약이 활성화됐다고 보고하지 않는다. 일일/주간 구분, 기간·중복 방지·리스·예약관리 제약·완료 건수 검증·화면/관측을 함께 수정하고 실제 요청량·사용량을 검증해야 한다. [정정 근거와 적용 범위](records/12_Meta_일일주간_정정_20261025.md)를 따른다. 기존 문서의 '2026-10-02 사용자 결정'이라는 Meta 주간 전용 기록은 이전 계획의 이력이며 현재 사용자 지시보다 우선하지 않는다.
Cafe24는 자사몰 1개 테스트 앱의 `mall.read_order` 내부 리포트 용도에 한해 Admin API 별도 이용료가 없다는 공식 파트너 답변을 확보했다. Meta 지원 담당자는 자사 광고계정의 `ads_read` 내부 보고 용도에 대해 Marketing API 자체의 별도 사용 비용·요금제는 확인되지 않고 광고 집행비만 별도라고 답했다. 두 답변을 다른 권한·계정·용도까지 일반화하지 않으며 Meta의 별도 계약·최소 결제 조건은 답변에 명시되지 않았음을 유지한다. 심사 면제와 요금 면제를 혼동하지 않는다. 자사몰 5개 이하 설치 경로, 개인개발자 개인정보 권한 제한, Meta 권한 액세스와 API 티어를 분리 확인한다. Google 접근 등급·버전은 구현일 공식 문서를 확인한다.
비밀값은 Git/문서/로그/응답/NEXT_PUBLIC에 기록하지 않는다. 비밀값 값 자체가 아니라 보호 저장 위치와 참조 이름만 인계한다. 고객 이름·전화·주소를 분석 수집·fixture에 포함하지 않는다.

## 데이터 원칙
카페24가 자사몰 매출 단일 원천이다. Meta·Google 전환매출은 합산하지 않는다. Meta 광고와 광고세트 비용을 중복 합산하지 않는다. Google 미매핑 비용은 공통 미배분으로 두고 상품별 반복 배분하지 않는다.
실패/미수집/미연동/정상 0/부분 수집을 구분한다. 원본 통화·시간대와 Decimal/BigInt 정밀도를 유지한다. 최근 성공 데이터와 최근 시도 상태를 분리한다.
매체별·계정별·기간별 입력 원천을 하나로 결정한다. CSV와 API가 서로 덮어쓰거나 중복 집계되지 않도록 전환 정책을 구현한다. 기존 수동 CSV 기능은 유지하며 자동화 범위와 충돌할 때 서버가 명시적 선택을 요구한다.

## 실행·검증
API 네트워크 대기 중 DB 트랜잭션을 유지하지 않는다. 계정별 DB 리스와 fencing을 쓰고, 메모리 작업만 띄운 뒤 성공 응답하지 않는다. 불완전 응답으로 기존 성공 데이터를 지우지 않는다.
현재 1GB 컨테이너, PRISMA_CONNECTION_LIMIT=3, HEAVY_OPERATION_CONCURRENCY=1, 절전·idle disconnect를 보존한다. 실제 값은 01에서 재확인한다.
각 단계는 관련 테스트만 먼저 수행한다. 최종 전체 lint/test/build와 컨테이너·브라우저 실검증은 10에서 수행한다. npm test에 포함된 e2e는 타입 검사일 수 있으므로 실제 브라우저 E2E 실행을 별도로 증명한다.
외부 심사·계정·요금이 막히면 독립 개발은 계속할 수 있으나 단계 완료와 운영 GO는 차단한다.
