## 작업
- [x] 입력 계약표를 작성한다. CSV 필드 → API 필드/변환 → 업무 의미 → 필수 여부 → 누락 정책 → 대조 샘플. Cafe24 결제/할인/쿠폰/취소/환불과 Meta 결과/기여기간/통화/상태/영상 필드를 포함한다.
- [x] Cafe24 현재 계산이 실제로 순매출인지 감사한다. 과거 환불을 어떻게 계산해 왔는지 기록하고, 자동화 때문에 과거 회계 의미를 조용히 바꾸지 않는다. 변경이 필요하면 구버전/신버전 호환·비교·전환 기준을 정한다.
- [x] provider+account/mall+shop+business key로 범위를 고정한다. 기존 계정 정보 없는 행은 명시적으로 기존 계정에 귀속하는 backfill 절차를 설계한다. 추정으로 다중 계정 데이터를 병합하지 않는다.
- [x] Google 정수 micros와 통화, Meta USD 기존 집계·환율, Cafe24 KRW를 구분한다. 통화/시간대가 다른 계정의 합산을 검증 없이 허용하지 않는다.
- [x] 공통 Connection/SyncRun/RunUnit/Lease/Coverage/SourcePolicy 계약과 Google 비용 테이블을 확정한다. 기존 Meta/Cafe24 전체 테이블을 범용 테이블로 교체하지 않는다.
- [x] CSV 유지·API 전환일·기존 행 식별·동일 기간 중복·수동 보정/재조회·원천 복귀 정책을 정의한다. 과거 CSV와 API를 같은 canonical key에 연결하되 기존 이력은 보존한다.
- [x] atomic publish 단위를 정한다. Google은 계정×날짜 완전 스냅샷, Meta는 성과 및 current/집계 일관성, Cafe24는 주문과 품목의 하루 완전 스냅샷이다. Cafe24 공급자 수정시각이 없는 실응답에 맞는 nullable 버전 계약은 06 미완료이며, API 응답에 없는 주문을 바로 삭제하지 않는다.
- [x] 수동·예약 endpoint/DTO/상태/권한/오류 코드·금액 문자열·coverage 응답을 확정한다. 설정 settings.manage, 수집 imports.manage, 조회 data.read, 예약 전용 machine guard; SYSTEM 감사는 실제 사용자 ID 위조 없이 저장한다.
- [x] additive migration 순서·구버전 읽기/쓰기 호환·source off·rollback 시 데이터 복원을 설계한다. 신규 FK/인덱스/RLS/grant와 제약 강화 시점도 적는다.
- [x] 용량 상한·기간 단위·로그 보존·실행 timeout·공정 순서·수집 완료 SLA의 초기 계약을 정한다. 2026-10-02 개정은 Cafe24 매일 전일 1일, Google·Meta 7일마다 직전 완료 7일이며 자동 재조회·월 보정은 폐기한다. Cafe24 02:00 기동/02:30 완료와 광고 원천 주간 시각은 실측으로 10에서 확정한다.
