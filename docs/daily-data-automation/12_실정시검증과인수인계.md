## 관측 계획
Cafe24는 매일 완료된 전일 주문일 **연속 3회**, Google·Meta는 각 계정 현지시간 기준 직전 완료 7일을 **7일 간격으로 연속 2회** 관측한다. 필수 날짜 범위가 확정 SLA 내 완료되지 않으면 원인 해결 후 해당 원천의 연속 성공 관측을 다시 시작한다.
이 단계는 며칠에 걸쳐 같은 계획서로 재개할 수 있다. 한 세션에서 장시간 대기하거나 미래 성공을 체크하지 않는다. 자율 후속 확인이 필요하면 사용자의 해당 시점 요청에 따라 지원되는 예약 기능을 설정한다. 계획 작성만으로 Codex 예약이나 별도 작업을 생성하지 않는다.
정상 0건 계정도 권한과 조회 범위·coverage가 검증되면 성공이다. 수동 POST/backfill 성공은 정시 실행 증거를 대체하지 않는다.

- [ ] Google/Meta 주간 지출과 Cafe24 전일 주문·매출이 같은 조건의 원천 보고서와 일치한다. 수집 후 늦게 수정된 값은 자동 보정되지 않는다는 한계와 수동 하루 재실행·마지막 성공 시각 표시를 확인한다.
- [ ] 정시 기동은 사용자의 PC/브라우저가 없어도 동작한다. 절전 상태에서 깨우기·idle 복귀를 실제 관측하며 점검 ping으로 절전을 방해하지 않는다.

- [ ] 실행시간·RSS·DB 대기·quota·새 고정비 여부·Railway/Supabase 사용량을 baseline과 비교한다. 3일 추정과 월 확정 청구를 구분한다.
- [ ] 미실행/부분 실패/토큰 문제 경고가 실제 관리자 화면과 외부 예약 기록에서 식별된다. 운영에서 고의 장애를 만들지 않고 실제 관측과 10 리허설 증거를 함께 사용한다.
