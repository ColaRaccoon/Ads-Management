## 실행 계약
기본안은 기존 Supabase Cron/HTTP/Vault 패턴의 독립 관리 함수 → Railway public Next 프록시 → 보호된 Nest 수집 경로다. 실제 HTTP 확장1.6의 옵션 미지원이 확인되어 10/15 새 격리 전용 Edge relay를 사이에 추가했다. DB→relay는 독립 Vault Basic/고정 HTTPS URL, relay→고정 Next 경로는 machine guard/redirect manual이다. native 첫 hop 자체의 no-follow는 보장하지 않으며 동일 신뢰 origin의 인증 유지와 cross-origin307의 인증 제외만 실제 확인했다. Nest loopback 4200에 외부 호출을 시도하지 않는다.
Cafe24는 매일02:00KST에 몰 현지 기준 완료된 전일1일을 읽는다. Meta는 매일02:03KST에 계정 현지 기준 완료 전일1일을 읽고,10/31 02:02KST부터7일마다 직전 완료7일을 추가 재조회한다. Google은 기존10/31 02:01KST부터7일마다 직전 완료7일이다. Meta 일일 첫 실행은10/26이며 같은 날짜의 주간 재조회는 canonical current를 교체하고 중복 합산하지 않는다. Google 우선 처리는 Cafe24의 매일 작업을 굶기지 않는 한도에서 검증한다. provider failure가 다른 작업을 영구 차단하지 않게 한다.
02:10/02:20 제한 재개와 02:30 Cafe24 미실행/미완료 점검은 초기 제안이다. Google·Meta 주간 작업은 별도 완료 한도를 측정한다. 실패 재시도는 해당 예약이 선정한 **동일 날짜 범위** 안에서만 허용하고 다음 예약에서 이전 누락 날짜를 자동 추가하지 않는다. 세 provider 분량·cold start가 시간 예산을 넘으면 격리 실측으로 단위/시각을 조정해 10에서 확정한다. 04시 Storage 작업과 겹치는 장기 작업을 방지한다.
