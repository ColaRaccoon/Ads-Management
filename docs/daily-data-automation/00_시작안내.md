# 카페24·Meta·Google 정기 데이터 자동화 실행 계획
작성일: 2026-09-21. 상태: 계획 작성 완료 / 구현·실계정 검증·운영 변경 미실행.

## 목적과 최종 완료
사람의 매일 파일 다운로드·업로드를 카페24 주문, Meta 광고 성과, Google 광고비의 정기 수집으로 대체한다. 초기 동의·심사·재인증·상품 매칭 예외 처리는 사람에게 남을 수 있다. 사용자는 실무에서 기존 프로그램을 매일 사용한다. **개발 중 운영 코드·DB·예약 작업을 변경하지 않고, 전체 후보 릴리스 검증이 끝난 후에만 운영 변경을 시작한다.**
최종 완료는 코드 완성이 아니다. 승인된 실제 배포환경에서 Cafe24의 매일 전일 1일 수집을 연속 3일, Google·Meta의 7일마다 직전 완료 7일 수집을 연속 2회 관측하고, 데이터 대조·기존 업무·복구·사용량 확인까지 12단계가 통과해야 한다. 배포 전 검증은 10단계, 배포 후 실제 정시 실행 확인은 12단계로 구분한다. 미래의 운영 성공을 배포 전에 확인했다고 주장하지 않는다.

## 한 세션의 작업 범위
사용자는 실행할 단계 파일 하나를 지정한다. 그 파일의 지정된 공통 문서와 인수인계 기록만 먼저 읽고, 그 단계만 구현·검증한다. 전체 계획을 한 세션에서 연속 구현하지 않는다. 작업이 컨텍스트를 넘으면 해당 단계 상태를 IN_PROGRESS로 남기고 같은 단계의 다음 세션으로 넘긴다.
각 파일의 필수 읽기는 짧은 공통 기준·확정 계약과 해당 영역 코드다. 이전 대화나 이전 단계 전체 계획을 읽을 필요가 없도록 records에 결론을 남긴다.

## 구글 원본 계획의 반영
[구글광고_데이터_자동화계획서.md](../../구글광고_데이터_자동화계획서.md)의 Google 우선 연결·Railway/Supabase 재사용·추가 비용 억제·카페24 매출 단일 원천·채널별 비용·자사몰 명칭·미배분 비용 원칙을 따른다. **2026-10-02 사용자 비용 결정이 원본의 최근 7일 반복 재수집·과거 자동 적재·월 보정 제안을 대체한다.** Cafe24는 매일 완료된 전일 주문일 하루, Google·Meta는 각 계정 시간대 기준 7일마다 한 번 직전 완료 7일을 수집한다. 세 원천 모두 자동 과거/월 대사와 누락일 따라잡기를 하지 않는다. 실패한 동일 범위의 제한 재시도와 관리자가 명시한 하루의 수동 복구만 허용한다. 이 절약형 정책에서는 늦게 수정된 매출·광고 성과가 자동 보정되지 않으므로 마지막 성공 시각·누락 날짜·수집 시점의 의미를 화면에 표시한다.
원본의 Meta/Cafe24 후속 제외는 이번 계획에서 해제한다. 카카오 실제 연동은 범위 밖이며 미연동으로 표시한다. 원본 13·15절의 기능별 조기 운영 배포는 **이번 사용자 지시에 따라 대체**한다. 01~10은 격리 환경, 11에서만 검증 완료 릴리스를 운영에 반영한다. 원본 기술 제안과 본 계획이 다르면 02의 결정 기록에 이유를 남긴다.

## 진행 확인과 요청 예
[진행표](진행표.md)를 단일 인덱스로 사용한다. 단계별 증거는 records/NN_결과.md에 남긴다.
다음 세션 요청 예:
> docs/daily-data-automation/01_운영기준선과접근조건.md에 따라 01단계만 진행해줘. 공통 운영보호 원칙을 지키고, 완료 증거와 다음 세션 인수인계를 기록해줘.
단계 번호를 바꾸어 동일하게 사용한다. 코드가 빌드된 것, 수동 실행된 것, 예약 등록된 것만으로 전체 완료를 선언하지 않는다.
