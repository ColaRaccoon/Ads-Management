# 06 — Cafe24 전일 주문·품목 수집
2026-10-06 사용자 업무 정의 정정: 쿠폰과 네이버페이 포인트는 제공 데이터만으로 정확히 분리할 수 없다. v1 쿠폰은 사용 표시가 있는 주문의 차액을 주문일·상품에 적용 가능한 내부 쿠폰 규칙과 대조하는 추정값이다. 실제 쿠폰 정답이나 CSV/API 결제액 전건 일치를 06 완료 조건으로 요구하지 않는다. 원천 금액의 정확한 파싱·출처, 쿠폰 사용 표시의 대응, 추정 상태·잔차와 기존 계산 흐름을 검증한다. 아래 미일치 관측은 보존하되 그 숫자만으로 계산 불가능 또는 미완료라고 판단하지 않는다. 해당 정책을 코드·계약에 반영했고 독립 평가와 실제 하루 발행·계산·실패 보존·철회/재연결·읽기 복구를 완료했다.

2026-10-06 v1 포함·입력 계약 보완: 9/21·9/30·10/1의 1,173품목 옵션/판매가·수량 실대조와 판매자 정의 옵션 확인을 바탕으로, 알려진 품목 상태의 **전량 주문 품목 투영**을 명시한다. C/R 품목도 공급자의 수량·판매가·상태를 그대로 보존하며 취소/반품 때문에 임의 제외하거나 별도 환불액을 차감하지 않는다. 이 기준은 환불 반영 순매출 또는 개별 환불액의 증명이 아니다. 미래 날짜마다 새 CSV 또는 exact-day 옵션/C/R 플래그를 요구하던 이전 조건은 폐기하고, 검토된 상태 코드 허용 목록·필드 형식·판매자 옵션 근거·매일 두 번 읽은 전체 주문/품목 키와 내용·충돌 없는 옵션 구성·정상적인 내부 규칙 조회와 명확한 매핑 상태로 대체한다. 정상 UNMATCHED는 원 품목을 보존하고 matched-only 계산에서 제외한다. 알 수 없는 상태·형식, 모호하거나 손상된 매핑, 규칙 조회 오류 또는 불완전 snapshot은 fail closed한다. CSV가 있는 날짜는 전건 업무 키/수량/판매가/옵션/매핑과 current/version/link를 검증하고, 선택한 금액 출처와 차이 집계를 보호 snapshot 지문에 결속해 명시적으로 검토한다. 날짜 없는 CSV의 과거 귀속 예외는 당시 검토한 내부 row UUID·version·link와 보호 내용 지문에만 결속하며 새 재업로드에 재사용하지 않는다.

API `totalPaidKrw`는 최상위 `Orders.payment_amount`의 출처를 고정 기록하고, 중첩 actual/initial의 결제액·상품 소계·배송비와 별도로 저장한다. CSV 총 주문금액과 같은 값이라고 가정하지 않는다. 쿠폰 입력의 `actual 상품 소계+배송비`는 명시적으로 선택한 추정 기준이며 미제공 성분은 null이다. 결제 코드 배열과 쿠폰 사용 신호 true/false/null을 보존하고, CSV 라벨 매핑이 없으면 `paymentMethod=null`로 저장한다. 신호·추정 기준이 미확정이면 `UNKNOWN`과 null 차감/마진을 전파한다. 포인트·적립금을 쿠폰으로 임의 분류하지 않는다. 실제 쿠폰 정답, 개별 취소/부분환불액, 환불 반영 순매출은 v1 결과로 주장하지 않는다. 실제 계산 진단은 충분한 기여 주문과 검증된 하루 범위에서만 비식별 집계를 내며 광고비 미수집은 null로 구분한다.

2026-10-07 실제 상태·미매핑 보완: 10/1 전체 읽기의 상태 집합은 C40·C48·E00·N30·N40·R00·R30·R40이다. 명시 검토한 N/C/R 코드와 정확한 E00만 v1 전량 품목 대상이며 다른 E/U 코드는 거절한다. E00도 전량 품목 승인과 정확 코드 승인을 함께 요구하고 원 수량·판매가를 보존한다. 취소/반품/교환 환불액을 만들어 차감하지 않는다. 정상 미매핑은 UNMATCHED/UNMATCHED와 null 상품·규칙 키로 전체 snapshot에 보존한다. CSV/API 매핑 metadata가 일치할 때만 전환하며, 매핑 오류·불일치는 거절한다. 미매핑 포함 성공에는 경고를 남기고 계산은 기존 mapped-only 범위임을 표시한다. 완전 수집이 전체 금액의 계산 완료를 뜻하지 않는다.

격리 복제 규칙의 DATE65/TIMESTAMP37 parser 오류는 실제 발행 전에 정정했고 CSV477 전건 매핑 metadata 변경0과 원 데이터·credential 보존을 확인했다. 날짜 정정 경로는 source 규칙을 READ ONLY로 재확인하고 비날짜 값·기존 구성 지문·행 잠금·정정 예정 규칙의 CSV 전건 매핑 동등성을 같은 트랜잭션에서 확인한다. 차이가 있으면 쓰기 전에 중단한다. 원래 CSV의 날짜·키·수량·금액과 credential은 날짜 정정 대상이 아니다.
