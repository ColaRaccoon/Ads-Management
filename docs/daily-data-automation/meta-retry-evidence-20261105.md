# Meta 수집 실패 진단과 제한 재시도

## 문제와 동작

11월 5일 Meta D-1 예약 수집은 `META_NORMALIZE_PROVIDER_ZERO_PROJECTION`으로 중단됐다. 0 기본지표 부모를 검증하는 함수가 내부 합계 불일치까지 하나의 ZERO_PROJECTION 코드로 덮어, 이미 허용된 BASIC_TOTALS/LINK_TOTALS/PURCHASE_TOTALS 예약 재시도에 도달하지 못할 수 있었다. 당시 실패 응답을 보관하지 않아 실제 내부 조건은 소급 확정하지 않는다.

이번 변경은 같은 함수의 검증 조건과 정상 데이터 결과를 유지하면서 실패 조건을 세분화한다. 계층별 광고비/기본지표·링크클릭·구매 합계 불일치는 기존 세 원인으로 전달한다. 이 경우에만 기존 예약 흐름이 새 capture를 재조회한다. 첫 시도 포함 최대 3회, 기존 cron 5분 간격/예약 창/lease/fencing을 유지한다. 세 번째 실패는 ACTION_REQUIRED다. 수동 실행, 인증, 원본 형식, 0 제외 증명 위반과 canonical 저장 실패는 이 재시도 예외에 포함하지 않는다. 일반 공급자 재시도 정책은 그대로다.

## 로그

- 실패 조건: 프로필, 통화/정수 형식, 관측된 활동, 구매 count/value null 쌍 불일치, 구매 0인데 양수 금액, 제외될 광고의 0 증명 위반, 계정 지표 null, 계층별 합계, 제외 멤버십, 남은 부모의 null 지표를 구분한다.
- 합계 오류: 계층, 지표, 자식/하위 광고 비교, 기대값/관측값/차이, 객체 fingerprint를 기록한다. 원본 이름이나 ID는 기록하지 않는다.
- capture: fingerprint, 관측 시각, 원본 계층별 행 수, 전체 페이지 수, 페이지 크기, pagination 완료, 계층별 페이지 수/받은 행 수/공급자 total_count(제공할 때만)/커서 종료 여부를 기록한다. cursor 원문은 기록하지 않는다.
- `MetaSyncRunnerService`의 `META_DAY_FAILED` 구조 로그와 기존 감사 이벤트 `SYNC_UNIT_FAILED` 또는 `SYNC_UNIT_ACTION_REQUIRED`의 `afterJson.metaEvidence`에 남긴다. 시도 번호/최대 횟수/재시도 결정을 함께 남겨 이후 성공해도 이전 실패 증거가 유지된다.
- 성공 로그 `META_DAY_SUCCEEDED`에도 원본 행 수와 저장 광고/광고세트 수 및 페이지 증거를 남긴다.
- 로그 입력은 닫힌 허용 목록과 길이/숫자 제한을 다시 검증한다. 원본 capture, 광고명, 토큰, 자격, 임의 예외 문자열은 기록하지 않는다. DB 스키마 변경은 없다.

## 검증

- 합계 오류가 정확한 원인과 기대값/관측값/차이를 유지하는지, 구조적 0 증명 위반은 재시도되지 않는지 검증했다.
- 실제 runner의 첫 불일치 시 저장 0회 → 새 예약 read 성공 시 저장 1회, 세 번째 실패 중단, 인증/수동/저장 오류 예외를 검증했다.
- 실제 foundation 실패 트랜잭션이 진단/시도/재시도 결정을 감사 이벤트로 전달하고, 허용되지 않은 문자열을 버리는지 검증했다.
- 실제 wire reader로 광고 1000+1행과 광고세트 314행 전체 조회를 검증했다. 공급자 total_count와 불일치하거나 다음 cursor가 반복되면 완료로 처리하지 않는다.
- 기존 정상 proof/hash·business row 불변, 부모 구매·V2 보고·진단 테스트 통과. API 타입/빌드 및 Web webpack 빌드 통과. 로컬 기본 Turbopack 빌드는 격리 worktree 바깥을 가리키는 의존성 junction 제한으로 실패해 webpack으로 별도 확인했다. 운영 Docker 빌드는 깨끗한 의존성 설치로 기본 빌드를 실행한다.
