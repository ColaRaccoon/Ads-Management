# 03 — 공통 수집·인증·저장 기반
상태: DONE (로컬 구현·격리 검증, 2026-09-29). 선행: 02 DONE. 증거: [03 결과](records/03_결과.md).
필수 읽기: 공통_작업규칙.md, records/02_확정계약.md, records/02_결과.md.
목표: 세 provider가 공유할 실행 상태·잠금·checkpoint·coverage·보안 기반 구현. 실제 provider 수집과 예약 등록은 하지 않는다.

## 구현
- [x] 확정된 additive Prisma migration과 runtime role grant/RLS 경계를 구현하고 격리 DB에서 적용한다. 운영 migrate dev/db push/reset 금지.
- [x] provider 모듈 비활성/미설정 시 기존 앱이 정상 부팅되고 외부 API·DB 폴링이 추가되지 않게 한다. 연결·수집·화면 활성화 상태를 분리한다. 화면은 09 범위로 현재 경로가 없으며 비활성이다.
- [x] 계정별 lease owner/generation/expiry, DB 기반 compare-and-swap/fencing, request idempotency, 날짜/주문 단위 checkpoint를 구현한다. 만료 후 이전 worker 쓰기 거부.
- [x] 실행 상태 RUNNING/PARTIAL/SUCCEEDED/FAILED/ACTION_REQUIRED 등의 전이와 lastAttempt/lastSuccess/coverage를 분리한다. 체크포인트와 업무 데이터는 동일 publish transaction에서 확정한다.
- [x] 전체 응답 메모리 상한·페이지 제한·짧은 transaction·deadline·bounded retry·Retry-After를 구현한다. HeavyOperationGate를 배경 실행에도 적용하고 수동 업무와 경쟁할 때 defer한다.
- [x] 머신 전용 인증, 기존 guard/CSRF/프록시 경계, 계정 allowlist, 기간 제한, secret 회전·로그 마스킹을 구현한다. 임의 URL/GAQL/SQL을 입력받지 않는다.
- [x] 인증정보는 보호 저장소를 사용한다. Cafe24 회전 refresh token은 암호화 영속 저장과 단일 갱신 락/CAS가 필요하다. 여러 worker 갱신 경쟁·응답 유실·저장 실패 시 기존 값 손상 없이 ACTION_REQUIRED로 처리한다. 암호화 키는 DB 밖에 둔다.
- [x] Google/Meta 정적 자격증명 참조와 Cafe24 동적 토큰의 수명·교체·재연결 계약을 마련한다. 모든 credential이 운영 변수 변경/재배포에 의존하는 설계를 피한다.
- [x] stale run 감지·재개 API·안전한 오류 응답·SYSTEM 및 사용자 감사 기록을 구현한다.

## 의미 있는 검증
- [x] 2개 실행 동시 claim, HTTP 중복, lease 만료 후 늦은 write, 저장 직전/직후 종료를 격리 PostgreSQL에서 검증한다.
- [x] 중간 페이지 실패와 rollback이 기존 성공 데이터·coverage를 보존한다.
- [x] 인증 없는 호출·권한 없는 사용자·잘못된 계정/기간·secret 회전 거부, 로그/응답 비밀값 미노출.
- [x] feature off 구버전 기능·신규 schema 구버전 실행의 호환성을 검사한다. 구버전 실행 증거는 HEAD Prisma client의 기존 테이블 읽기·쓰기·rollback smoke이며 전체 구버전 API 부팅은 10에서 다룬다.
- [x] API 대기 중 DB 풀 점유와 작업 종료 후 idle disconnect를 검사한다.
