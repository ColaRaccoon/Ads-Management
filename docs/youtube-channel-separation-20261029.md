# 유튜브 판매의 메타·구글 중복 연결 분리

실제 로그인한 운영 UI에서 구글 SALE 상품 전체 매핑을 먼저 등록했다. 카페24 계정 `be140e7e-3994-406e-94ff-b50dfc7ac7b2`의 `180 → 풀업바`, `179 → 버닝웨이브바`이며 시작일은 기존 해당 주문의 첫 날짜인 **2026-10-19**, 종료일은 없다. 별도 판매 구성 금액을 넣지 않아 기존 날짜별 비용 규칙을 유지한다.

그 뒤 관련 현재 주문 47개 레코드만 메타 미매칭 상태로 바꿨다. 원본 금액·수량·옵션·수집 원천·계정 연결·원천 선택 정책은 변경하지 않았다. 규칙 2개 및 주문 47개 각각의 변경을 SYSTEM 감사 이력으로 기록했다. CSV 오류 목록과 배치의 경고 수도 함께 갱신했다.

## 과거 CSV 처리

과거 CSV의 쇼핑몰 연결값이 비어 있으면 구글 매핑도 조회되지 않는 문제가 있었다. 이미 수집 원천 선택을 통과한 CSV에 한해, **전체 등록 카페24 쇼핑몰이 정확히 하나인 경우** 그 쇼핑몰의 명시적 구글 매핑을 조회하도록 보완했다.

전체 계정 수를 별도로 조회하므로 화면에서 쇼핑몰 하나를 선택해도 여러 쇼핑몰의 소유권을 추정하지 않는다. 계정 없는 API 주문은 추정하지 않는다. 날짜별 적용 범위와 `[유튜브]` 조건도 유지한다. 원본 CSV 계정값이나 수집 정책을 바꾸지 않고 이전 구글 판매수량·매출·판매비용·쿠폰을 보존했다. 기존 과거 기간의 수집 미완료 상태를 확정으로 변경하지 않는다.

## 정비 스크립트와 증빙

`scripts/youtube-channel-separation.ts`는 이번 정비에 고정된 스크립트이며 정기 동기화 작업이 아니다. 기존 `productionCafe24Db`의 대상·인증서 검증을 사용한다.

- 기본 실행: 유튜브 상품 전체 조회 및 최초 변경 전 증빙 저장.
- `--history`: 10월 19~22일 구글 결과를 최초 증빙으로 저장.
- `--plan`: 규칙 변경과 기존 구글 매핑을 사전 검증. 쓰지 않는다.
- `--apply`: 원본 증빙과 일치하는 규칙 2개·주문 47개만 단일 트랜잭션으로 수정한다. 원본 입력이나 일반 주문 연결이 바뀌면 롤백한다. 커밋 후에는 재실행을 거절한다.
- `--verify`: 전체 유튜브 연결 해제, 금액·일반 매핑 보존, 과거 구글 결과 및 10월 28일 양쪽 결과를 비교한다.
- `--ready`: 이번 배포 SHA와 운영 준비 상태를 확인한다.

정비 증빙과 복구용 이전 매핑은 실행 PC의 임시 폴더에 `youtube-channel-before-20261029.json`, `youtube-google-history-before-20261029.json`, `youtube-channel-operation-20261029.json`, `youtube-channel-after-20261029.json`으로 저장했다. DB 자격 증명은 기록하지 않는다. 이후 데이터가 새로 수집되면 전체 입력 해시는 달라질 수 있으므로, 이번 고정 증빙을 새로운 시점의 기준으로 재사용하지 않는다.
