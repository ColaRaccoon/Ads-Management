# 보안 개발 환경 운영 안내

이 문서는 보안 작업용 worktree의 로컬 개발 환경만 설명한다. 운영 `.env`, 운영 DB, 원본 업로드·보고서 파일을 이 worktree로 복사하지 않는다.

## 고정 경로와 포트

| 항목 | 보안 개발 환경 |
|---|---|
| worktree | `C:\Users\seong\Desktop\workspace\Meta-Ads-Performance-security-rbac` |
| branch | `codex/security-rbac` |
| Web | `3200` |
| API | `4200` |
| PostgreSQL | `127.0.0.1:55432` |
| DB data | `.security-dev/postgres-data` (Git ignored) |
| uploads | `apps/api/storage/security-dev/uploads` (Git ignored) |
| reports | `apps/api/storage/security-dev/reports` (Git ignored) |

PostgreSQL은 운영 Supabase와 다른 로컬 PostgreSQL 17 물리 클러스터다. `meta_ads_security_app` 전용 로그인 역할과 `meta_ads_security_dev`, `meta_ads_security_test`, `meta_ads_security_shadow` DB/schema를 사용한다. 실제 접속 암호와 URL은 Git ignored `apps/api/.env`에만 있으며 문서나 로그에 기록하지 않는다.

## 로컬 DB 시작과 종료

PowerShell에서 다음 명령을 사용한다.

```powershell
$worktree = "C:\Users\seong\Desktop\workspace\Meta-Ads-Performance-security-rbac"
$pgData = Join-Path $worktree ".security-dev\postgres-data"
$pgLog = Join-Path $worktree ".security-dev\postgres.log"

& "C:\Program Files\PostgreSQL\17\bin\pg_ctl.exe" -D $pgData -l $pgLog -w start
& "C:\Program Files\PostgreSQL\17\bin\pg_ctl.exe" -D $pgData -w stop
```

이미 실행 중인지 먼저 확인하고 중복 기동하지 않는다. 종료할 때는 반드시 위 `$pgData`가 보안 worktree 아래인지 확인한다. Windows의 기존 `postgresql-x64-17` 서비스나 업무용 프로세스는 중지하지 않는다.

## Web과 API 실행

API는 `apps/api/.env`의 `PORT=4200`과 격리 DB/storage를 사용한다.

```powershell
Set-Location "C:\Users\seong\Desktop\workspace\Meta-Ads-Performance-security-rbac"
npm.cmd --workspace @meta-ads-performance/api run start:dev
```

Web은 package script의 3100 고정값을 사용하지 않고 포트를 명시한다.

```powershell
Set-Location "C:\Users\seong\Desktop\workspace\Meta-Ads-Performance-security-rbac\apps\web"
npx.cmd next dev -p 3200
```

`apps/web/.env.local`은 `/backend-api`를 `http://127.0.0.1:4200/api`로 프록시한다. 2단계의 Supabase Auth 값은 사용자 승인과 별도 개발 Auth 프로젝트 준비 전에는 추가하지 않는다.

## 금지 사항

- 운영 `.env` 또는 실제 URL/비밀번호/token/API key를 복사·출력·commit하지 않는다.
- 개발·테스트·shadow URL을 운영 Supabase로 바꾸지 않는다.
- 운영 DB에서 migration, seed, 테스트 SQL을 실행하지 않는다.
- 원본 `apps/api/storage/uploads` 또는 `reports`를 개발 경로로 지정하지 않는다.
- 3100/4100 프로세스나 Windows PostgreSQL 서비스를 강제 종료하지 않는다.
