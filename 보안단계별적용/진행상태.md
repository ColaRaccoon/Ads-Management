- 운영은 원격 Supabase, 개발은 loopback 전용(`listen_addresses=127.0.0.1`) 로컬 cluster다. 물리 cluster/host가 다르다.
- 개발 역할은 `NOSUPERUSER`, `NOCREATEDB`, `NOCREATEROLE`, `NOREPLICATION`이다. 로컬 dev/test/shadow DB에만 connect/schema create 권한이 있고 로컬 `postgres` DB에는 connect할 수 없다.
- 운영에서 확인한 application schema `meta_ads` 및 `auth`, `extensions`, `graphql`, `graphql_public`, `pgbouncer`, `realtime`, `storage`, `vault`는 개발 cluster에 존재하지 않는다. 따라서 개발 역할이 운영 schema에 접근할 경로가 없다.
- 실제 URL/비밀번호는 각각 Git ignored `apps/api/.env`, `.security-dev/postgres-admin.password`에만 있다. 운영 `.env`와 개발 `.env`의 SHA-256은 다르며 파일을 복사하지 않았다. 실제 secret은 출력·문서화·commit하지 않았다.
- `SHADOW_DATABASE_URL`을 Prisma datasource에 연결했고 dev/test/shadow DB와 schema를 분리했다.
- 개발 DB에 기존 migration 28개를 적용했다. 새 migration과 seed는 만들거나 실행하지 않았다. 첫 deploy는 기존 첫 migration의 `CREATE SCHEMA IF NOT EXISTS public`에 필요한 로컬 DB `CREATE` 권한이 없어 첫 문장에서 실패했으며, 로컬 3개 DB에만 권한을 부여하고 공식 `migrate resolve --rolled-back` 후 재실행해 28개가 모두 적용됐다.
