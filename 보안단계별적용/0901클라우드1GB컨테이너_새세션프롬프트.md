최종 목표는 기존 Supabase Pro의 Auth, PostgreSQL, private Storage와 1GB 상시

기존 업무 기능, RBAC, 감사, DTO, 파일 검증, Storage abstraction을 재사용하고
중복 구현하지 마라. LAN/Windows 산출물은 역사적 기록으로 보존하며 cloud mode에서
실행되지 않음을 먼저 증명한다. 섣불리 대량 삭제하지 마라.

운영 Supabase DB/Auth/Storage, Koyeb 계정, Git remote/registry, 외부 배포, DNS,
원본 main 또는 원본 업무 프로세스는 승인 없이 변경하지 마라. 외부 상태 변경이
필요해지면 계획서의 해당 gate에서 정확한 대상, 실행 내용, 영향, 비용, 성공 판정,
rollback을 제시하고 사용자에게 명시적으로 승인받아라. 비밀값과 개인정보는 출력,
로그, 문서, Git에 남기지 마라.

1GB 제한에서 최대 upload/bundle/report와 동시 요청의 RSS/heap을 실제 측정하고,
OOM을 숨기지 마라. 목표를 지키지 못하면 동시성·파일 상한 조정안과 2GB 승격안을
근거와 함께 보고하라. staging/production PASS는 실제 승인된 target에서 수행한
항목만 기록하고, 외부 검증 전에는 operationalReady=false를 유지한다.

종료 전 prisma validate/generate, 전체 lint/test/build, git diff --check, container
cold start/health/signal/1GB 테스트를 실행하고 결과를 진행상태.md에 기록하라.
